# Word 内容体裁与原生排版

先区分创作、整体美化、局部编辑和格式转换。创作需内容方法与结构；整体美化保留事实、优化层级；局部改字/字体不重建整篇；格式转换不能改变原意。当前实时内容服务无需先生成 HTML 再转 DOCX，也不强制三次角色切换。

| 体裁 | 结构重点 | 质量尺度 |
| --- | --- | --- |
| 商务报告 | 摘要、证据、问题与建议、行动 | 指标口径、来源、事实与推断分开 |
| 方案 | 目标、约束、选项、步骤与验收 | 可执行，责任与时间只写已知信息 |
| 会议纪要 | 背景、讨论、决议、待办 | 不把建议写成已决定事项 |
| 技术文档 | 问题、设计、使用步骤、例子与限制 | 参数和示例真实，不虚构测试通过 |
| 学术/合同/公文 | 按用户要求采用明确结构 | 正式规范需核实；不编引文或宣称合规 |

内容组织先于装饰。一个主标题、连续的章节层级、适度段落与有意义的列表。关键结论必须有证据；不同地区数据颜色语义可能不同，默认通过文字/符号解释，不仅靠红绿。不要把所有关键数字强制标红。

用当前可用字体和支持样式形成一致层级，例如标题20–24pt、章节14–16pt、正文11–12pt、说明9–10pt作为商务起点，按要求调整。原生样式fontSize是pt，表格列宽是px，不混用。默认行距和间距由编辑器提供；无需为普通短文发现所有字体。精准分页、完整页眉页脚和目录域未支持时不得承诺。

表格用于比较和结构化数据，不用于整篇模拟页面布局；明确表头、单位、列宽和文字换行，长表按内容拆分或说明限制。图片给有效alt和解释；不把文字截图当可编辑正文。当前表格/图片用原生 block 模型，禁止向 document 操作提交 HTML/CSS、CSS变量或腾讯装饰组件。

美化前先读取用户当前版本。替换 block 时保留未要求变动的 style、list、table、image 字段，省略可能重置格式。缺少完整封面/分页能力时用支持的标题与层级交付，明确具体限制而不是停在排版计划。
