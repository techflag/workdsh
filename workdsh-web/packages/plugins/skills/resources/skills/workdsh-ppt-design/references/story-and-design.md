# PPT 叙事与视觉系统

先明确受众、场合、核心目标、页数、必讲事实、风格和内容边界。已有答案直接使用，能合理确定的命名与一般布局可先起草。缺少业务事实保留未知；不反复问已提供信息。

每页确定：要观众记住的一句话、主要证据、布局、视觉载体和与前后页的关系。汇报通常先结果，再证据与解释，最后行动；教学可以先问题与概念，再例子与练习。按真实内容选择，不把所有任务做成日报模板。

数字需说明含义或影响，但推断必须有依据；7/10=70%可以说明进度，不能无依据声称同比增长或全部当天交付。目录若存在必须与实际章节一致；短稿不用为补目录增加页数。用户要求三页时优先组织成三页，不能为了模板扩页。

## 页面节奏与布局

区分焦点页、信息页与过渡页。焦点可用巨型指标、产品图或关键观点；信息页承载图表、证据和解释。不要连续重复相同卡片排列；也不用强制百分比配额限制所有稿件。极简风格不靠补空话达到字数下限。

| 内容 | 合适布局 | 检查 |
| --- | --- | --- |
| 核心指标 | 大数字与事实解释，封面可用非对称色块 | 数字明显大于正文，单位明确 |
| 趋势或完成情况 | 大图表加短结论 | 图表标签可读，结论与数据一致 |
| 对比 | 主次双栏或统一比较表 | 比较尺度相同，不制造虚假差异 |
| 流程或架构 | 关系图或分阶段路径 | 连接关系正确，可编辑且不遮挡 |
| 行动 | 编号任务、负责人/时间/验收（仅已知内容） | 未知项注明，不编造承诺 |

先选择具体视觉系统：背景、正文、强调与辅助色，标题/正文/关键数字层级，页边距、对齐锚点、页脚。默认商务可用白底、深蓝正文、蓝色重点、浅蓝辅助；风格由用户主题决定，不能所有稿件都套蓝卡片。颜色按语义使用，警告色不用于所有普通重点。

以实际画布宽高为尺度，例如左右安全边距约画布宽的4–6%；数字层级约为正文的2–4倍，具体字号受原生 schema 限制。不要把腾讯 JSX 的 px、CSS 阴影、渐变或字体字段直接复制成原生属性。主题与支持字段从当前能力返回核对。

主视觉应支撑观点：数据页用图表，结构页用图解，场景页使用实际可获得的素材。图像不是必需配额，缺图可以用真实指标和编辑器支持的结构化视觉。按内容调整容器高度，留白围绕焦点；提交前检查边界、文本裁切、意外遮挡、卡片间距和页脚。
