# 网站价值叙事与应用设计

先理解产品、受众、主要目标、价值区别、品牌、内容与技术约束。用户已有充分资料直接使用；不强制每次多选所有章节。问题只针对会改变实现的缺口，合理假设注明，不把模拟用户访谈当真实研究。

落地页先内容再视觉：首屏清楚说明产品、价值和下一步，用真实截图或演示让功能可理解。按目标选择解决问题、核心功能、工作方式、真实证据、FAQ或价格，不一律堆十个章节。没有用户评价、合作客户、统计或定价就不造内容。每个区块推进叙事，避免重复功能卡。

Web应用先考虑主要任务、信息密度、导航和操作状态。表格、表单、搜索、详情与反馈服务实际流程；空、加载、失败、成功状态要清楚。应用内部视觉服从现有WorkDSH规范，不能把营销页大标题与夸张动效搬进工作台。

选择明确设计语言，用具体令牌表达字体层级、背景/文字/重点/边界色、间距、圆角和交互状态。保持组件一致，适量改变版式与视觉节奏。不要为“高级”添加无意义渐变、玻璃或图标；图片、纹理、动效应帮助表达产品。

主要CTA要有真实动作；未接入注册、付费或发送功能不能伪装成功。常见结构包括Header、Hero、核心功能/演示、必要支持区块、Footer，用户范围优先。假设与占位项供审阅，不当作上线成品。
