# 网页制作：从需求到可使用工程

本流程用于现有文件/工程工具，不提供设计画布、服务器或发布服务。用户已有技术栈、品牌、目标与页面时直接使用；只确认影响实现或外部行为的缺口。

## 选择实际交付方式

- 修改现有网站：先读工程说明、路由、组件与构建脚本，保留用户内容和约定。修复一个页面不升级框架或重新创建工程。
- 无既有工程的展示页：优先选择无需构建的语义 HTML/CSS/JS；内容适合单文件可内联样式，否则使用相对路径的 assets。字体、图片缺失时使用明确的可用替代，不依赖用户机器上的文件。
- 有状态的 Web 应用：沿用既有框架；没有工程时按任务选择最小结构。先实现核心任务和状态，不用看似完整的后台页面伪装未实现服务。
- 设计稿转代码：分析层级、布局、组件与素材，再转成流式布局。精确复刻固定画布仅在用户明确要求时采用，并说明目标尺寸；普通网站必须能响应式重排。

选择既有约定可直接继续，不为排版或每个区块反复请求确认。登录、发送、支付、外部数据等未接入时标明演示边界；用户输入不暗示可以对外提交或发布。

## 实现顺序

1. 用已有事实明确读者、首要任务、主行动和必要页面；说明不可猜测的内容。已有来源URL实际查看，不把参考内容当成授权。
2. 建立页面结构与少量设计令牌：字号、行高、颜色、间距、容器宽度和焦点状态。保留可用素材，记录素材来源；不要虚构客户评价、数量、奖项或定价。
3. 先完成一条可运行的核心路径，再补次要区域。导航指向真实页面/锚点；主要按钮必须执行明确动作。空态、失败、加载和成功按实际功能设计，不把模拟结果称作真实数据。
4. 完善窄屏、桌面、键盘操作和减少动效。中英文按内容组织，标题、正文、按钮、表单、替代文本和元信息都覆盖；没有用户双语要求时不强制增加语言切换。
5. 使用工程原有命令构建或检查。有真实预览/浏览器工具时启动可停止的本地预览，验证主要路径并查看截图；不能只生成截图文件而不阅读就声称视觉通过。不要默认机器有 Python，也不为静态预览引入新框架。
6. 修复观察到的错误后复验对应路径。没有浏览器能力时交付文件并明确视觉未检查；不无限重复已经通过的无关测试。

## 最终交付契约

交付真实存在的成果，不只回复页面大纲或“开发完成”：

- **入口**：可打开的 HTML 文件或工程主入口，所有必要 CSS/JS/图片一起保留。文件或官方文件展示工具提供的引用必须实际存在。
- **运行说明**：使用工程已有命令，写明工作目录、运行时要求、构建方式；纯静态页面说明是否可直接打开。说明哪些功能需要服务或配置，不包含任何凭据。
- **预览**：可用时给当前可访问的本地地址；端口和服务器退出后失效的边界明确。预览与部署分开，未部署不声称上线。
- **检查结果**：列实际检查的屏幕尺寸、语言、关键交互和构建结果，说明未检查项目；没有自动化检查不编造测试数量。
- **已知限制**：待补的素材、后端、真实数据或上线配置，准确区分演示与完成。

用户需要下载工程时，通过已有受权文件/归档工具将必要源码与素材打包，排除 node_modules、缓存、.env、凭据和用户无关数据。没有归档工具时提供工程目录和入口，不编造下载链接。官方 present 可用时展示真实文件，失败明确说明并保留可用路径。

GitHub Pages等部署只在用户请求发布且有真实仓库/流程时执行，核对路径前缀、资源链接与刷新；线上地址以实际部署回执和访问检查为依据。不要以本地 localhost 冒充线上交付。

## 示例及反例

展示页：为一个已有产品制作中英文介绍页，主CTA链接真实下载页；没有用户评价就不加评价区。检查语言切换、移动导航、键盘焦点、资源路径和入口文件。

应用：读取用户提供的本地样例，制作可筛选的订单看板；交付明确标记样例来源的筛选/空结果/详情状态。无API时不能声称连接了订单系统，也不能让“导出”仅弹成功提示。

反例：只有1440像素固定布局；页面能看但CTA无动作；所有语言只有导航变化；工程缺图片或运行说明；服务器已退出却称预览可用。这些都不满足对应的交付要求。

## WorkDSH 单文件实时网页

普通 HTML 看板先用 content_open(kind:html,source:new) 打开右侧预览；不要先独立写完文件。读取当前能力和修订，通过 html.replaceDocument 提交完整 HTML，先有用首屏再逐步完善。使用内联 CSS/JS/SVG，无外部 CDN。预览与源码均可查看，最终 content_export 交付真实 HTML。已有独立 HTML 暂无自动导入，多文件或服务器应用沿用工程流程。

## 可交付网页的验收门槛

工作副本已打开、代码已保存和视觉已验收是三种不同状态。正式交付前，有浏览器能力时验证：

- 目标桌面宽度、实际窄侧栏宽度和约 390px 手机宽度（用户指定尺寸优先）；整页无非预期横向溢出，导航不逐字竖排，关键数值/图表可读。表格内部滚动可以保留。
- 至少一条主要路径：导航/筛选/详情/语言切换等按本次实际功能选择；同时检查空结果和错误反馈，不虚构后台服务。
- 查看最终截图，并核对关键组件计算样式和控制台错误。截图文件存在不算已阅读；JS 正常也不等于 CSS 正常。
- 最后一次实质修改后复验受影响区域；导出的文件与最后提交的工作副本一致、样式和脚本完整、资源确实可用。单文件实时预览使用内联 CSS/JS/SVG，不依赖外部 CDN。

按腾讯 core workflow 的分级验证思想，在区域完成/全局样式变更/最终集成这些边界检查，不在每次微小文字更新后跑全量截图。观察到问题先定位布局、选择器或资源根因，只复验相关路径；同一区域连续两次修复仍失败时，保留成果并说明具体缺口，不无限自称完美。

缺少浏览器工具时，完成源码级检查和真实文件交付，明确“视觉未验证”及待检查项，不将这类结果称为已通过响应式验收，也不冒充自动验收服务。
