# 完整技能包制作与交付

采用 WorkBuddy 的完整方法，以入口 SKILL.md 的六步流程为主；创建端和安装端分开。

1. 在工作区 skill-drafts 下初始化，显式指定 --path。通过 Harness 实际 resourceBase 定位内置 scripts，命令里的占位路径必须替换。确认 Python3 和执行工具存在。
2. 先制作真实 references/scripts/assets，再编写 SKILL.md。复制用户模板时核对原文件与副本字节；不要用描述替代二进制素材。删除初始化的演示脚本、参考和资产，解决全部 TODO。
3. 运行 python3 <resourceBase>/scripts/quick_validate.py <草稿目录>；修正名称、目录、占位符和相对引用。此标准库校验不等于 Harness YAML 解析或专业质量验收；官方导入预检仍是安装关口。
4. 运行 python3 <resourceBase>/scripts/package_skill.py <草稿目录> <输出目录>。检查退出状态、ZIP 实际存在及文件清单，必要时比较模板字节。ZIP 保留单一技能根目录，排除缓存文件。
5. 使用典型输入试用，检查真实产物，并增加不适用请求和缺输入的情形。只执行可用工具；测试脚本遵守当前执行审批。没有真实试用就写未执行。
6. 提供真实 ZIP 下载链接、名称、适用范围、资源数量、检查结果与未验证项。通过技能导入界面预检并确认安装；不能把包制作完成写成已经安装。

简单的无资源技能可继续走 save/validate/publish 草稿工具。完整资源更新必须保留旧版，导入同名冲突不得绕过。用户未请求重启、安装或发布插件时，仅更新工程资源并交付结果。
