# 从真实任务形成可复用技能

先利用用户已有的输入、样例和成果要求，必要时补充一个典型例子。明确哪些请求应触发技能、哪些相似请求不适用；description 用于准确路由，正文承载实际方法。

对每个例子推导：输入与约束→实际操作→重复或易错环节→可复用资源→独立验收。不要先创建三个空目录再声称能力齐全。

| 任务特征 | 资源 | 最低使用契约 |
| --- | --- | --- |
| 重复计算、转换或检查 | scripts | 参数、依赖、输出、失败行为，真实执行证据 |
| 领域规则、schema、API | references | 来源、读取条件、相关段落与使用方法 |
| 品牌、版式或工程骨架 | assets/templates | 实际文件、用途与生成成果方式 |

顺序依赖强时给流程与各阶段输入/输出；多个独立操作给任务目录；规范遵守给规则及例外；综合能力可以混合。创建与编辑分支分开。严格数据格式用固定模板；分析报告提供柔性默认结构及证据要求。

示例：月度销售分析需真实销售表和口径，检查缺失/重复，按指定维度计算，区分异常与解释，交付报告及核验数字。schema 放参考，重复计算用脚本；不可凭示例数字填真实成果。

示例：PPT 制作先明确受众、叙事与来源事实，再决定版式、品牌和资源；内容、渲染检查、可编辑性与最终 PPTX 文件分别验收。“精美”不是完整操作说明，也不能以 Markdown 大纲代替 PPTX。

保留非显而易见的专业知识、判断尺度、反例和输出标准。删掉初始化 TODO 与演示占位文件。涉及仅建议的方法明确等待审阅，不虚构客户、履历或业务成绩。
