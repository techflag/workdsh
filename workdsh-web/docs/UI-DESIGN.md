# WorkDSH 页面风格与交互规范

版本：1.0，2026-09-10。适用于用户端、管理端及所有功能插件页面。

本文件是后续 UI 开发的统一约束。依据用户提供的 WorkBuddy 截图及纠偏要求整理；具体尺寸为 WorkDSH 实施基线，不声称是 WorkBuddy 官方设计参数。当前原型仍有占位素材和未完成交互，不能视作用户已批准的最终设计。

## 1. 基线与优先级

用户明确反馈 > 本规范 > 当前原型。截图用于对照布局、密度与视觉层级，原型出现偏差时修复原型，不反过来修改规范为错误实现背书。

风格采用中性灰黑、紧凑导航、明确内容层级、小面积浅灰主按钮。禁止自行加入绿色品牌主题、营销式大标题、超大文字卡片、英文装饰标语或无功能意义的序号。首页和能力中心的场景缩略图可以有内容色彩，应用框架保持中性。

[交互原型](ui/index.html)只供审阅；[历史提案](ui/DESIGN-HISTORY.md)仅解释演变，不作为现行规则。D01 接入探针不作为产品视觉模板。

## 3. 字体与密度

使用 PingFang SC、Microsoft YaHei、sans-serif；中文正文正常字重 400，标题 500—600，不对所有文字加粗。

| 元素 | 字号 / 行高 | 规则 |
| --- | --- | --- |
| 首页主标题 | 30 / 42px | 单一居中标题，不加营销副标题 |
| 页面分区标题 | 20 / 28px | 如精选场景、专家 |
| 顶部标签与侧栏 | 14 / 22px | 图标与文字垂直居中 |
| 专家卡片标题 | 14 / 22px | 单行省略，完整名称可访问 |
| 项目动态正文 | 15 / 27px | 正文不塞进事件卡片 |
| 输入文字 | 15 / 24px | 输入提示不淡到难以辨认 |
| 卡片描述 | 12 / 20px | 最多两行，详情页完整展示 |
| 辅助文字、标签 | 11—12 / 18px | 仅用于非主体信息 |

基本间距采用 4、8、12、16、20、24、32px；不要在每个页面随机决定间距。按钮常规高 32—36px、导航项约 34—38px；纯图标热区至少 32px，小屏触控目标至少 44px。

## 4. 图标与素材

- 所有操作图标使用同一套 SVG，24×24 viewBox、1.7px 描边、圆端点和圆连接，不混用字符、emoji、图标字体代替按钮图标。
- 导航图标显示 20px，工具栏 18—20px，配置加号 19px；固定 28—29px 图标槽位。极小下拉箭头 12—13px。
- 图标按语义选择：日常办公用杯子；资料库用书本；权限用盾牌；数据分析用图表。不能因为形状接近就任意替代。
- 纯图标按钮必须有可访问名称，悬停提示不得代替名称；装饰 SVG 使用 aria-hidden。
- 专家头像与导航图标是两类素材：头像 35—40px、圆形；技能可以用彩色字章；连接器使用清晰的连接定义标识。
- 场景封面和案例缩略图保持一致比例，文字覆盖处加暗层。素材必须记录来源或自制方式，不靠模糊、滤镜或放大截图补细节。
- 当前本地人物轮廓和场景色块为占位，不能计为最终头像/封面完成。正文中的 emoji 仅允许作为用户或示例正文内容。

## 5. 页面骨架

### 全局框架

桌面主参考视口 1440×1000，另测 1920×1080；浏览器缩放 100%，记录 CSS 视口与 deviceScaleFactor，不能比较不同缩放截图后凭感觉调整。

左侧保留 Harness 官方 Sidebar 的宽度、折叠和响应式行为。工作区按官方语义显示为一级文件夹，所属会话缩进在其下；创建工作区、搜索/筛选、工作区重命名/删除、会话重命名/分叉/归档、时间和折叠行为必须由官方 occupant 提供，禁止用 WorkDSH 列表复刻。助理、项目、“专家 · 技能 · 连接器”、定时任务、资料库和更多通过官方 `sidebar.panellist` 增量加入新会话与工作区之间（2026-09-17 用户决定：助理、定时任务、更多 尚无领域实现，先隐藏入口与占位页，实现后恢复）；能力中心保持一个入口，进入页面后再分专家、技能、连接器，不能替换整块 sidebar。

原生桌面交通灯只属于实际桌面窗口；Web 正式产品不模拟可点击窗口控制。当前原型保留装饰是为了截图对照，不作为 Web 功能要求。

### 首页

“新建任务”直接使用 Harness 原生 `main.conversation` 空会话与 `EmptyHero/InputBar`，不注册 WorkDSH 自建首页输入器。该入口必须原样继承 `/` 指令、`@` 文件或对话引用、附件、权限、模型、Agent preset、发送和取消管线；任何 WorkDSH 业务快捷入口只允许把内容或稳定引用交给这些公开接口，不能复制编辑器或绕过官方提交链。

工作区列表位于左侧并按官方 Workspace/Session 关系分组；工作区行负责展开或收起，会话行打开已有原生 Session。点击“新建任务”清除当前 Session 后进入官方空会话，由原生 WorkspaceChip 选择工作区，因此创建前仍可切换目录。旧 `workdsh-view=home` 地址只作兼容入口并归一化为 `workdsh-view=conversation`。

参考图中的日常办公、代码开发、设计创意、快捷能力和案例属于后续业务发现层。只有在它们能通过公开 preset、command、skill 或 draft 接口接入同一原生编辑器后才实现，不得先放置无真实能力的平行输入框。

### 能力中心

顶部直接排列专家/技能/连接器标签、右侧搜索与“我的”入口，不设置营销标题。（2026-09-20 用户决定：行业应用暂时用不到，删除能力中心该标签入口；应用域规划与模块不删除。）

专家发布前以已保存且校验过的定义提供完整使用预览，包含专业设定、真实固定技能与示例；预览不自动试用或发布。采用公共Modal，正文内部滚动、确认操作固定；完整内容可审阅，不能仅展示60字截断摘要。版本摘要收在辅助详情里，用户先看到用途和专业内容。

专家使用详情默认呈现已发布版本；若有已保存且不同的草稿，向可编辑用户提示“草稿有修改，尚未发布”，给出版本对应技能数量和编辑草稿入口。编辑器说明保存与确认发布的区别；未保存内容只在编辑器提示，不冒充服务端草稿。额外能力声明与真实配备技能分区；尚未实现接入校验时不能标注为实时检测的“未满足”。

专家页：精选场景横向滚动 → 专家/专家团与排序 → 分类条 → 四列专家卡片。场景卡约 235px 宽、210px 高；专家卡内边距 18px、圆角 17px，头像与名称/副标题同排，两行描述，底部标签。不能退回三列巨大空卡。低于 1150px 可三列，窄屏两列或一列。

搜索、分类和排序组合生效；无结果保留筛选条件。悬停操作必须也可键盘聚焦、触屏访问。我的专家内提供创建/编辑；不能因对齐截图丢失管理入口。

技能和连接器使用同一骨架但各有字段：技能展示来源/安装状态，连接器展示授权与连接状态，禁止照搬专家身份字段。

### 项目

顶部面包屑与邀请；主区直接以动态/计划/任务/资产开头，不增加项目大标题占位。项目配置在右侧，约主区分配后的 20.4vw（建议 280—360px）。

动态为留言流：发布留言、与我相关/成员动态、作者和时间、正文。输入区保持在主区底部，动态区域独立滚动。配置顺序：指令、连接器、专家、技能、定时任务。计划待办与执行任务分开。

### 任务、资料库和管理端

任务中间为原生对话与执行记录，右侧成果与预览；不得生成一套假的执行状态。资料库采用列表/表格为主，名称、位置、所有者、时间层级清楚。管理端使用同样颜色、字体、控件，独立入口和权限，不能变成另一套视觉产品。

## 6. 状态与交互

每个页面在实现时必须覆盖：加载、空数据、搜索无结果、正常、失败、无权限、离线/重连。写操作另覆盖提交中、冲突、部分成功与结果未知；只有真实回执才能显示成功。

对话框统一标题、右上关闭、明确取消/确认，焦点进入并受控，Escape 按场景关闭，关闭后回到触发元素。危险操作解释目标和影响；重试不能自动重复不确定的远端提交。

空状态简短说明并给一个主要下一步。规划中的功能标明未实现，不制造成功响应。示例原型必须持续显示“示例数据”；正式产品去掉开发标记和 Host/Remote 等实现细节。

## 7. 工程落实与变更

packages/ui 在 D02 起承接 token、基础控件及纯展示组件；workbench 拥有框架与导航，功能插件通过公开接口贡献视图。禁止复制全套页面 CSS 到各插件，禁止横向导入其他领域内部组件。

现有 docs/ui 中累积的 CSS 覆盖仅是设计迭代产物，不是正式组件实现模板。正式承接前必须去重、抽取 token、整理响应式规则，并与本规范逐项比对。不得为复制视觉绕开 Harness 公开 Slots/Client/Remote 或另造运行时。

新样式先判断能否复用已有 token/组件。确需新增时，记录用途、影响页面和截图，再更新规范；用户修正应同时更新规范、原型与验收记录，避免只修当前页。UI 版本不改变 D01—D15 业务开发门槛。

## 8. 交付检查清单

每次 UI 交付在 STATUS 记录范围、测试和剩余差异：

- [ ] 同一视口/缩放截图对照，检查栏宽、标题位置、内容密度与滚动。
- [ ] 图标风格、字号、对齐与热区一致，没有字符占位操作图标。
- [ ] 键盘导航、焦点、弹窗、长名称、空状态和组合筛选可用。
- [ ] 1440/1920 桌面与 390px 小屏无意外横向溢出。
- [ ] 头像、封面、缩略图来源明确；占位与最终素材区分。
- [ ] 页面和相关插件的真实检查通过；原型测试不冒充业务验收。
- [ ] 记录无法达到参考的公开接口限制和待补项，不宣称整体一致。

当前已有四页截图与原型交互回归；尚未完成所有表单、组合筛选、可访问性、最终素材和正式组件迁移。以上清单是后续执行门槛，不是本轮全部完成声明。

## 9. 资料库专项布局补充

参考用户资料库对照截图，资料库必须采用“全局导航 / 资料库导航 / 资料列表”三栏，不能沿用大标题加单表格模板。资料库二级栏宽约 18.5vw，建议限制在 235—300px；主区独立滚动，内边距约 45px。

二级栏包含：资料库标题、搜索、最近、本地产物；我的资料及创建入口；团队空间及新增入口；底部容量展示。主区标题为当前视图名称（如最近），不要增加英文装饰和营销文案。

主区依次为：最近访问/我分享的/与我共享分段控件与类型筛选；名称/所有者/位置/最近访问四列；了解资料库与两张引导卡片。名称带语义明确的文件类型 SVG，长名称省略，行高约 48px，不使用大块留白卡片。容量与分享状态必须来自实际服务；示例数据不能表示真实配额或权限。

搜索与类型筛选组合生效，切换分享范围保留明确当前选中态；无资料与筛选无结果分开。低宽度可隐藏次要时间列，但详情中仍可访问；二级导航在小屏折叠或纵向排列。当前原型提供布局和本地示例筛选，不代表导入、分享或存储实现。

## 10. 项目配置右栏细则

右栏使用 280—360px 限制宽度（约 21.2vw），窄桌面可缩至 250px。左右内边距 16px，标题行 24px，标题下间距 16px；卡片圆角 12px、边框 #393939、横向内边距 12px、卡片间距 12px。容器必须设置 min-width:0，并实测卡片右边缘不越界，不能靠裁切隐藏问题。

配置标题 14px/20px、字重 500，计数 12px/400、间距 6px。加号为 18px SVG、32px 热区；标题、计数与按钮共用一行。项目栏中的紧凑头像为 24px，技能字章 21px，间距 10px，允许窄宽度换行；专家目录仍按第 4 节使用较大头像。

定时任务用 6px CSS 状态点，不用字符黑圆点与全角空格定位；名称 13px/20px，时间 11px/18px，名称与时间左边线一致。状态含义由文字或可访问说明补充，示例色点不能当作真实调度状态。查看全部保留文字按钮。示例标识统一放在原型顶部，避免在每张卡重复堆叠开发说明。

## 11. 共用配置弹框

专家、技能、连接器配置复用 ConfigDialog 与 ConfigItem。桌面宽 840px、高 590px，分别受视口减 32px/48px 限制；背景 #202020、边框 #3b3b3b、圆角 24px、黑色遮罩约 70%。标题区与底部按钮固定，中间区域独立滚动。标题 18px，正文左右内边距 24px，底部通过分隔线区分，按钮右对齐。

配置列表两列，间距 12px，卡片内边距 16px；头像 36px，与单行名称、说明同排。小屏单列。专家/技能使用取消与确定；连接器使用个人授权/公共授权切换、说明和关闭按钮。添加必须指向真实选择流程，未实现时明确提示，不伪造保存成功。

原型共用实现见 ui/components；领域数据在 project-dialogs.js，展示组件不拥有权限、存储或跨插件调用。D02 正式迁入 packages/ui 时保留受控状态、提交失败与处理中语义。关闭恢复焦点，Escape 可退出，图标按钮具备名称。

## 12. 公共组件范围与应用入口

公共组件按展示职责划分，统一放入 packages/ui（正式实现从 D02 承接）：

| 分类 | 共用内容 | 领域保留内容 |
| --- | --- | --- |
| 基础 | 颜色/间距/字号 token、SVG、按钮、输入框、标签、头像、状态点 | 品牌及业务数据 |
| 导航 | 导航项、分组、面包屑、标签页、分段选择 | 路由与功能注册 |
| 容器 | 配置弹框、抽屉、分栏、滚动区、固定操作栏 | 权限和提交结果 |
| 列表 | 图文卡片、资源行、搜索工具条、空状态、加载/失败反馈 | 专家/技能/资料字段与查询 |
| 交互 | 菜单、提示、确认、分页、选择列表 | 业务校验与保存 |

任务输入与对话使用 Harness 原生 Conversation 的 `/`、`@`、附件、权限、模型、preset、审批、取消和状态服务；WorkDSH 不创建通用 Composer 公共组件，也不建立第二套执行状态。工作台整体布局由 workbench 插件拥有，不把路由、组织状态或 Host ctx 塞进纯 UI 包。统一规范允许不同页面骨架，禁止全部套用一种卡片页。

应用入口区分当前事实和目标：当前安装 bundle 仍显示 Harness 默认外壳，只增加 WorkDSH 接入验证导航；docs/ui/index.html 是独立原型，未接入运行时。目标是在专用 WorkDSH Profile 中，通过公开 Client 插件与 Slots 组合提供 WorkDSH 首页、导航及功能页面，继续由 Harness 启动并管理会话。安装插件本身不等于自动更换外壳。

D01 后续必须验证：公开布局/Slot 的替换范围、默认首页选择、官方设置与会话入口保留、刷新恢复、卸载后默认客户端恢复。尚未通过前不承诺截图级完整外壳替换。不得用隐藏默认 DOM 的 CSS、iframe 嵌入原型或第二个 React 根绕过限制。D02 根据探针结果实现组合；若存在公开接口缺口，记录具体限制再决定呈现方式。

依据：官方 Web Client 架构 https://deepseek-harness.github.io/deepseek-harness/reference/subsystems/web-client ，以及本地 docs/evidence/d01-client.md 的已验证导航/主区接入证据。

## 13. 插件入口与运行范围分别管理

是否显示导航不等于是否安装、启用或授权。全局/会话描述运行范围；主导航/设置/上下文/无页面描述 UI 贡献，两者不得混为同一种分类。没有导航的插件可以正常提供工具或服务；隐藏按钮不能作为鉴权。

| 功能 | 目标入口 |
| --- | --- |
| workbench | 首页及整体导航组合 |
| projects、library、automations | 主导航独立页面 |
| experts、skills、connectors | 同一个能力中心的不同标签；项目内另有配置弹框 |
| applications | 应用选择入口与场景页面 |
| admin | 有权限成员的独立组织管理入口 |
| identity、access、audit、model-policy、usage | 设置或管理端按职责呈现；不逐个占主导航 |
| providers | 配置/诊断或纯服务，不自动注册主导航 |

公开 rc.1 npm 包核对：sidebar.panellist 注册 id/label/order，main 使用相同 key；sidebar.brand.mark/name 提供品牌位置；sidebar.settings 提供底部设置席位；ctx.layout.selectPanel(id) 选择全局面板，null 返回会话，不改变当前 Session。插件可以提供多个 UI 贡献，也可以完全不提供 UI。

当前官方 AppFrame 的左栏默认 280px、可调 264—420px，布局状态刷新重置；因此原型尺寸和刷新恢复不能直接视为原生行为。优先使用公开品牌/面板扩展验证，再评估外壳替换。SSH 截图只能证明有底部入口和全局插件条目，不能据此断言其具体使用哪个 Slot；本项目不依赖 SSH 私有实现。


## 14. 执行组合的产品呈现

普通用户从新建任务、专家、项目或应用进入任务，默认展示已验证组合；不要求先理解四种底层模式。高级执行组合选择与专家选择分开，只在创建前或原生允许的空会话显示切换。明确展示能力说明与不可用原因，不把模式选择当权限开关。

创建专家/技能/应用进入各自受控创作流程，复用弹框、选择器、校验反馈与发布状态。不能直接将“创造模式”包装成已经保存成功的管理功能。组合变更需要新任务时明确提供交接入口；自动化配置展示组合、执行主体及失效诊断。

## 15. 正式 WorkDSH Profile 的页面映射

正式应用继续由 `dsh web` 启动，浏览器只存在官方 Client module loader、Cordis Client Context 和 React root。WorkDSH bundle/Profile 组合官方会话能力和自有 Client 插件，打开后的稳定结构如下：

```text
官方 Web Client
├─ 左栏 sidebar（官方 owner）
│  ├─ WorkDSH 品牌 mark/name
│  ├─ 官方新会话与 Session/Workspace 列表及全部菜单
│  ├─ WorkDSH 业务面板入口（按已安装、授权且可用的插件增量贡献）
│  └─ 官方设置 + 有权限时的管理入口
├─ 主区 main
│  ├─ 原生 Conversation：任务、流式回复、工具、审批、附件、取消
│  └─ WorkDSH 面板：能力中心、项目、资料库、自动化、管理端
├─ 会话右栏 rightbar.session
│  └─ 文件、资料、成果及业务页面的会话级预览
└─ shell.overlay
   └─ 共用弹框、选择器与短时浮层
```

| 设计对象 | 正式扩展点或数据路径 | 约束 |
| --- | --- | --- |
| 品牌 | `sidebar.brand.mark`、`sidebar.brand.name` | Profile 只选定一套品牌胜者；卸载后恢复官方贡献。 |
| 主导航 | `sidebar.panellist` + 配对 `main` entry | entry id 稳定；入口可见性来自安装、能力健康和权限的共同结果。 |
| 原生任务 | `main.conversation` | 由 `selectPanel(null)` 返回；不复制输入、历史或运行状态。 |
| WorkDSH 页面 | `main` 下的业务 panel | Host → Remote → Client model → Slot props；组件不直接持有 Remote 或 ctx。 |
| 项目资料/成果预览 | `rightbar.session`、自有 tab kind 或 `dsh-resource://` 协议 | 只承载会话级预览；项目配置留在项目 main 页面。 |
| 对话内业务卡片 | Session event → Conversation Definition → target renderer | 必须可回放；临时组件不能代表持久业务结果。 |
| 公共弹框 | `shell.overlay` 或所属页面局部层 | 复用 packages/ui primitive；权限校验和保存仍走领域服务。 |
| 设置与插件诊断 | `sidebar.settings` 子 slot / `settings.plugins.tab` | 展示 ACTIVE/PENDING/FAILED、版本、依赖和入口位置。 |

原型的灰黑视觉只描述产品方向。正式组件优先使用官方 `ui-primitives`；WorkDSH 的 packages/ui 只补没有对应 primitive 的展示组合。样式使用 `--dsw-*` 语义 token、CSS Modules 和 `clsx`，不复制原型中的硬编码色板，不引入 Tailwind 或第二套全局主题。弹框、菜单、输入框使用官方 elevation；平面中性分隔线为 0.5px。每个新增组件同时验证键盘焦点、减少动态效果、长文本和明暗主题。

插件没有左栏入口是允许的：领域 provider、身份、授权、审计和模型策略通常只提供服务或设置项；SSH 一类显式底部按钮属于该插件的 UI 选择，不是所有插件的强制模板。管理端是有权限时显示的 WorkDSH main 面板，共享同一 Host 和组件规范，不另起管理应用或数据库。

## 16. 设置卡与工具结果卡

设置项使用官方设置布局和 keyed slot，由同一功能包提供配对的 Host descriptor 与 Client card。卡片只编辑该插件的运行偏好，显示来源、当前修订、生效方式和冲突；组织策略、连接密钥、领域对象不能塞入通用设置 JSON。密钥字段只显示引用或“已设置”，不提供读回。

对话内工具结果卡通过官方 Client `tool.call.toolview` keyed contribution 注册。Host 只产生规范结果及纯 presentation metadata，Client model 校验 wire event/meta 后传给展示组件；缺少 renderer、数据版本未知或插件卸载时使用官方通用工具视图。业务成功以领域回执为准，不能由卡片是否渲染推断。

设置卡、工具卡、配置弹框、列表和状态提示共享 `packages/ui` primitive；各插件保留查询、权限、提交、取消与错误映射。Client bundle 不横向导入另一个功能插件的实现，跨域状态通过公开 contracts/Remote/Session 投影传入。

## 17. 正式界面与原型对齐（用户纠偏）

能力页直接使用专家/技能/连接器分类工具栏（行业应用标签按 2026-09-20 用户决定删除）、右侧搜索、“我安装的 N”入口和“添加技能”。技能页是用户或组织的全局技能库，不显示任务选择器；所有 WorkDSH 业务任务默认解析全局技能层，项目与 preset 只增加受控范围或覆盖。任务页可展示本次运行最终解析结果，但不能反向成为技能所有者。当前产品没有 SkillHub、套件和可靠的技能分类元数据，不展示空标签、虚构分类或无动作筛选器。

信息架构可以保留“已安装/公共技能”两个范围，但当前不开发公共市场，只展示 Harness 默认/本地已安装集合。分类在企业版设计中是独立目录对象，不写入 Harness 官方 frontmatter。未来企业服务端返回真实 taxonomy 且至少存在两个有效分类后，才显示可操作分类筛选；当前没有数据时只显示“全部”和已安装集合。

“添加技能”展开三项菜单：查找技能、上传技能、创建技能。查找技能聚焦并使用当前已安装目录搜索；在真实市场服务出现前不伪造外部搜索结果。上传技能打开共享 Modal 装配的领域弹框，支持拖入或选择 `.zip`、`.md` 与文件夹；上传后先显示名称、说明、文件清单、体积和安装范围，只有显式确认才安装。创建技能进入 Harness 原生任务，默认草稿为 `/skill-creator 请帮我创建一个可以实现「……」的 skill`；原生 `/` 解析为技能标签，输入区继续保留 `@`、附件、权限、模型、preset、发送和取消。完成创建或导入后由官方 watcher 刷新目录，随后可在任意适用任务用 `/name` 调用。

“我安装的”是市场页内的独立视图：市场头部“我安装的 N”入口进入，页面含“全部技能”返回链接、计数标题、“批量管理”与“搜索已安装的技能”页内搜索，卡片、批量与详情复用市场同一实现；进入与返回重置面板滚动并把焦点分别迁移到返回链接与入口。列表采用紧凑卡片，展示真实名称、摘要和调用状态；选择卡片进入独立详情层，返回后保留列表条件。详情顶部包含返回、标识、名称、摘要与“去试试”；试用通过官方 Session 和 Conversation 预填 `/name`。概述区只渲染 Host 契约实际返回的正文与元数据。编辑、打开目录、启停和卸载必须分别接入授权、路径及冲突处理，不得以无动作菜单或仅改 Client 状态模拟。长列表进入详情必须重置内容滚动位置。

正式工作台的外观由官方 ThemeRuntime 与用户偏好驱动：设置页的浅色/深色/跟随系统即时生效，不注册第二套主题、不拦截 theme/change，也不写用户全局主题偏好。普通入口不显示接入诊断；调试 query 可显式开启。

验收深色外观时必须在真实 Host 页面检查 sidebar 与内容同时为深色，不能只对主面板截图。原生导航与全业务导航之间剩余差异单独记录，不靠示例数据填充。

## 18. 正式公共侧栏切片

依据用户图2验收基准及 ADR 0014，workbench 使用公开 `sidebar.brand.*` 与 `sidebar.panellist` 增量提供 WorkDSH 品牌和中文业务导航；不替换 root、layout 或 sidebar owner，也不声明原生 owner 已拥有的子槽。新会话、顶部工具、工作区/Session 分组和固定设置底栏继续由 Harness 官方组件布局；WorkDSH 导航统一 SVG、34—38px 行高。Web 不绘制假的交通灯。

真实任务标题、顺序、工作区归组和菜单全部由 Harness Sidebar owner 提供，无示例计数。项目空间未实现时展示待开放，不拿本地 Workspace 当业务项目。待开放入口 disabled 且附原因；全局技能库与任务列表互不筛选，任务中的可用技能只作为运行时解析与诊断视图。

不再提供“更多/返回 WorkDSH”的双侧栏往返。官方 Sidebar 始终存在，设置、工作区和会话操作保持原生入口；WorkDSH 只增加公开 Slot 允许的业务入口。设置相关业务说明应放在对应业务页面，不能拦截或仿制 Harness 原生设置流程。

图标、导航行、分组、令牌和业务弹框样式由 packages/ui 共用；Harness 原生设置保持官方组件。领域插件只提供内容与动作。能力卡片的全部抽取仍待实施。验收必须使用正式 Host 截图，不以原型图片替代。

## 2026-09-22 公共控件统一

以 Harness 原生 Button/Input 为基础；普通表单与工具栏统一 36px，紧凑行内操作 28px。同组控件同高，宽度按内容设置。主按钮使用 primary，次操作 outline，轻操作 ghost。Select/Textarea 在公共 UI 补齐，颜色使用官方语义变量，不引入 shadcn 或全局 button 覆盖。旧页面样式置于业务层，原生控件样式拥有控件外观，业务类仅用于布局和专用组件。

## 2026-09-22 项目详情修订
用户授权以任务为默认页，计划/资产/活动记录依次排列。单机活动使用紧凑日期分组；计划默认文本和状态标签，点击后编辑，明确保存/取消与错误保留。任务标题、来源、时间、打开入口对齐，配置修订不占据列表。配置显示完整名称，压缩空状态；定时任务未实现时不提供无效添加按钮。保留官方主题与原生任务运行。

### 项目输入区级联菜单（2026-09-22）
“＋”的能力分类使用锚定输入区的二级面板；悬停、点击均可打开。空态就地显示，不以大模态框打断输入。列表可搜索，保存中禁用重复操作，失败留在原面板说明原因。窄屏同位置切换单面板并提供返回；Escape 和点击外部可关闭。项目配置语义须明确标注，不能把项目绑定冒充原生会话的临时专家切换。
