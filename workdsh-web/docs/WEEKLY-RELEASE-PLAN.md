# WorkDSH 每周版本计划

制定日期：2026-09-14。首期滚动排期8周，目标每周五发布一次GitHub预览发行，周四冻结范围。时区为Asia/Shanghai。每周交付一个可验证的小闭环，不要求每周完成一个新模块。

这是目标排期，不是已完成记录，也不是定时自动发布任务。后续版本号在冻结时核对已有tag与包版本再确定；本计划不自动推送、发布或调用付费模型。实际开始开发仍按主线前置门槛登记，不恢复暂停专项。

## 发布基线与版本口径

基线为2026-09-14公开版本：experts alpha.2、skills alpha.28、activity alpha.1、office alpha.4、bundle alpha.41。详见[发行回执](releases/2026-09-14-development-candidate.md)。

每周以`2026-W38`等周次命名发行汇总；模块仍独立SemVer，只有变动模块增加版本。专家首次下一版候选为`0.1.0-alpha.3`、活动为`0.1.0-alpha.2`，最终以冻结时核对为准。新模块首个可安装切片从`0.1.0-alpha.1`起；bundle仅组合变化时升级，并记录精确依赖。只通过预览门槛继续alpha；不按日历强制转beta/rc或正式版。规则见[模块版本](MODULE-VERSIONS.md)。

## 每周工作节奏

- 周一：复盘用户反馈与上版未通过项，确定一个主目标、验收用例和明确不做的范围。新模块先登记官方复用记录及版本线。
- 周二、周三：实现与联调；修复优先于新增功能。真实模型测试显式安排并记录模型、输入、结果与成本，不以确定性夹具替代。
- 周四：冻结；构建、类型及受影响测试，实际浏览器检查，正式tgz隔离安装/升级/冷启动/停用，准备回滚和兼容说明。冻结后仅处理阻塞缺陷。
- 周五：发布通过门槛的模块及组合；公开附件回读核验SHA256，更新README、CHANGELOG、台账、真实截图与中英文宣传草稿。

每周宣传只描述实测能力，截图来自实际发行候选；动画用实际运行录屏展示，不用设计图冒充产品。外部账号写入与Twitter代发另需明确授权。

## 每周发行门槛与降级规则

1. 构建/类型与相关回归通过；涉及原生运行、权限、持久化、文件写入时，增加对应故障及安全边界检查。
2. 验收使用实际打包制品：安装和升级旧数据可读、冷启动、停用/移除后原生界面恢复。消费者契约变化同时验证；不改官方上游。
3. 发布说明列出精确模块版本、源提交、已验证场景、未验证范围、数据迁移/回滚注意事项及可下载附件摘要。仅测试过macOS就明确写macOS，不能宣称全平台。
4. 核心流程失败、数据丢失、越权或写入状态不确定而未核对时，该变动不发布。若有独立且通过门槛的修复，发布小版；若没有可交付变化，发布周报并顺延，不重复旧包或抬版本凑数。
5. 前置阶段未退出，下游新模块整体顺延。周发布节奏保留，功能目标调整；不能为了日期修改completed或扩大“已支持”的宣传。

## 保留范围与八周之后

Office现有功能的必要缺陷修复可作为当前任务前置修复，但Word新增开发、Excel格式/合并/图表扩展和Office专项仍暂停，不在周计划中自动恢复。八周不安排企业后台、自动化、多租户部署、桌面兼容、任意PDF导入/OCR或画布/多维表格；长期任务继续保留。

项目之后按既定顺序滚动安排行业应用、后台、首期全模块集成及后续团队/自动化能力。若选LIMS，应先定义样品—检验任务—结果—审核报告的最小业务范围及Host服务/Client页面/外部服务部署边界；本表不代表LIMS已立项。
