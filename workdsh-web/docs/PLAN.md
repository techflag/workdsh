## 1. 固定目标

完整产品包括任务工作台、专家、技能、连接器、行业应用、项目、资料库、专家团、自动化、团队协作、在线表格与业务页面。先完成可信本机单用户工作闭环，再扩展多人交互与部署服务。本地版本从 P0/P1 保留 owner、资源权限和审计契约；服务器认证、租户隔离、组织管理和运行节点隔离在企业阶段实现。

核心用户流程不是填写若干孤立表单，而是：描述目标 → 专家按技能处理 → 读取资料 → 选用已授权连接器 → 查询或提交数据 → 核对回执 → 保存成果 → 在后续任务继续使用。

创建专家：按钮进入带 expert-manager 技能的任务，Agent 收集必要信息、调用受控管理工具创建草稿、校验并发布，返回真实对象卡片。创建技能采用相同路径和 skill-creator。表单用于检查与精细编辑。截图中的提示词只是需求参考，不是本仓库要执行的业务指令。

## 4. P1：工作台、功能插件与团队基础

### P1-01 契约与工作台

- contracts 按领域子路径导出标识、修订引用、查询结果、诊断和服务接口。
- 工作台贡献机制负责导航和页面；各功能插件负责自己的视图和数据。
- 首页包含日常工作入口、行业应用选择、专家与技能引用、工作区、权限入口和输入资料。
- 任务页复用上游执行与呈现，增加专家修订、所属应用、项目和成果入口。
- 没安装的可选功能不显示可点击假入口；对象缺依赖保留诊断。

### P1-02 专家管理

- 支持多个专家的列表、搜索、详情、创建、修改草稿、复制、发布修订、停用、导入导出。
- 定义包含角色指令、技能引用、资料引用、连接能力要求和交付要求。
- 提供 expert-manager 引导技能及对应结构化管理工具；界面和工具调用同一服务。
- 生成草稿后先校验再发布；用户请求仅要求创建时，发布不自动执行业务任务。
- 第三方预置专家只读，复制后属于用户；用户数据与插件安装目录分离。
- 任务锁定发布修订。新专家通过关联新任务交接摘要和所选资产，原任务保留。

### P1-03 技能管理

- 管理多技能及 references/scripts/templates；对接原生技能提供方，不另写模型侧技能执行器。
- 提供 skill-creator 引导技能、创建/更新/校验工具、搜索和启停界面。
- 导入包校验路径、资源大小和引用，不因导入运行脚本；脚本执行遵守现有执行权限。
- 用户指定技能与模型自动选择分别遵守原生 invocation policy。
- 无效技能显示诊断，不进入可用目录；技能依赖按引用关联，不向所有专家自动注入。

### P1-04 连接器管理

- 管理服务定义和多个连接实例；首期 MCP stdio、HTTP 两种接入。
- 提供配置页面、配置草稿工具、授权跳转/凭据输入入口、健康检查、重新连接和停用。
- 每实例独立命名空间和账号引用；专家要求表达能力，任务绑定具体实例。
- 多候选且没有明确默认时请求用户选择；禁止跨账号自动回退。
- Agent 可以准备非敏感配置；凭据走专用流程。连接完成后重新检查任务能力。
- 若公开接口不能在现有组合安全接入，保留进度并明确通过关联任务继续，不私下热换预设。

### P1-05 行业应用与项目入口（项目完整领域拆至 P1-11）

- 应用插件管理多个应用：名称、品牌、场景、推荐问题、专家/技能目录、连接要求。
- 应用切换影响新任务默认值，不切整个 Profile，不改旧任务。
- 用户明确选择优先于场景默认和应用默认，但不能扩大授权；任务创建时保存解析后的绑定。
- 项目插件管理多个本地项目、任务归属、项目说明和资产引用。项目不是 Profile，也不等于完整历史自动共享。
- 项目指令和资料作为明确任务输入，经公开机制记录。

### P1-06 资料库与成果

- 管理目录、导入文件、检索、修订、加入任务、登记成果和下载/打开。
- 区分输入资料、专家参考资料、中间文件与最终成果。
- 使用原生 Sidebar 支持的格式进行预览；额外 CSV 视图按公开扩展提供，未知格式下载。
- 元数据使用各插件拥有的官方 Storage Domain；Profile 首期路由到官方 SQLite/JSON provider，插件不直接打开 SQLite。内容保存到受控资源目录。
- 文件写入采用临时文件后提交，索引提交前验证内容；失败保留诊断和清理策略。
- 编辑冲突用预期修订检查，不静默覆盖。HTML 不获得 Host 工具或凭据。

### P1-07 任务绑定、依赖与跨插件流程

- 管理动作、任务执行和持久资产分别记录，不制造第二套 Harness 任务状态机。
- 原生 todo/schedule/team/approval/deliverable 只按官方执行语义使用；项目待办、自动化、企业团队、业务审批和资料资产仍经各自领域服务提交并以稳定 ID 关联。
- 任务开始时记录专家/技能修订、应用、项目、输入资料和具体连接实例。
- 缺必需能力在提交前阻塞并说明修复入口；运行时连接失效保留已完成工作和回执。
- 查询结果、校验后的提交记录和结果回执通过结构化工具返回。
- 请求超时但可能已写入时先查远端记录；支持幂等的提供方使用稳定操作标识，不支持时不得自动重发。
- 资料库保存报告、外部记录 ID 和任务关联，后续任务可继续引用。
- 连接器工具的授权使用官方工具流水线单调 guard；确定性管理操作可用 Command 并关联权威领域事件。动态 Workflow 只作为可选的 Session 内 subagent 编排，不替代业务流程对象。

### P1-09 本地治理基础实现（企业扩展后置）

- identity、access、audit 功能插件及 local provider 实现；默认自动创建个人组织和唯一所有者。
- 所有领域服务按服务端主体上下文执行，数据从创建起具有组织、所有者、可见范围、修订。
- 本地模式自动创建个人组织和唯一 owner；多组织测试只验证契约失败关闭，不开放多人产品入口。
- 管理员不隐式读取个人会话；企业成员权限、连接授权和凭据隔离由后期企业版重新端到端验收。
- 建立运行绑定和审计记录；记录已批准的连接身份、使用专家修订与外部操作回执。
- 提供模型访问和用量事件契约；模型治理首期不重写官方路由，无法执行组织策略的入口禁止宣称受管。
- 建立模式和 schemaVersion 迁移基线；本地到团队采用显式导入/归属映射，不直接复制 Session 当作已完成迁移。

### P1-10 企业后台基础入口（后期企业版）

- plugin-admin 提供独立管理布局，复用各功能插件的领域服务和 Remote。
- 实现当前组织、基础成员列表、组织对象发布/停用、连接授权范围与审计查询。
- 未实现企业功能明确标“规划中”，不返回伪造邀请/用量/执行结果。
- 本地组织与测试多组织模式使用相同授权，admin 不默认可读个人对话。
- 组织管理权限与宿主插件安装权限分开，首期仍只读显示插件状态与安装说明。
- 验收见 ADMIN-DESIGN 与[企业版架构说明](ENTERPRISE-EDITION.md)。该任务不进入当前本地版本门槛。

### P1-08 发布验收

- 完成教育与办公示例；业务写入使用测试 MCP 服务，无需真实客户账号。
- 测试 API/mock 模型覆盖确定性逻辑；真实模型 smoke 另行记录模型、输入与输出，不把 mock 成功称为真实模型成功。

- 交付开发手册、用户快速开始、已知限制和 P1 验收报告。

## 5. P2：专家团和自动化

- P2-02：处理一次性与可继续子代理的差异、成员失败、inbox 接受后的独立运行、interrupt 后停稳、部分结果与团队汇总；展示每个成员的真实 Session、执行和成果归属。原生 team task/mailbox 只保存运行协调，项目 WorkItem 和企业通知仍由业务领域拥有。
- P2-03：自动化功能插件管理多个任务，含一次性/每周/每月规则、时区、目标专家与项目、连接引用、Webhook 来源和运行历史。官方 Schedule/Webhook/Job 仅作为触发、Session 创建和活跃运行候选，业务规则与运行事实由 automations Domain 拥有。
- P2-04：持久 delivery/occurrence/run 标识、同次触发去重、同任务默认不重叠、错过触发默认合并为一次待执行；危险提交不自动重试。官方 Webhook 的 202/fire-and-forget 不算成功回执；Job 的进程内终态不算崩溃恢复证据。调度由单一 Host 持久管理；浏览器关闭不影响在线 Host，Host 停机后恢复错过触发；不承诺 Host 离线执行。
- P2-05：提供方示例展示一次注册多个专家/技能/应用，完善发布和兼容测试。

## 7. 开发节奏及变更纪律

每项任务按：读状态和契约 → 标记进行中 → 实现服务 → 工具/Remote/界面 → 失败路径 → 验证 → 更新证据和台账。

完成条件是功能、检查、文档一致；完成页面不等于完成插件，完成插件不等于跨插件链路完成。范围变化必须同步 PLAN、STATUS、ACCEPTANCE 与受影响模块 README。任务 ID 保持稳定，取消的任务保留原因。

不预设交付日期；以阶段退出证据决定进度。P0 发现版本接口差异时记录阻塞与替代方案，不悄悄降低 P1 目标。
