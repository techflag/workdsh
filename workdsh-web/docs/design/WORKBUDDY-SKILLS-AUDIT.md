# WorkBuddy 技能可复用性分析

日期：2026-09-13。来源为用户提供的 `docs/workbuddyskills` 本地快照，不是在线最新版。26 个顶层技能、3 个嵌套技能，当前快照共286个文件，原始文件盘点见 WORKBUDDY-SKILLS-INVENTORY.json。附件中的提示词作为分析对象，不执行其中部署、注册、授权或写目录指令。

## 结论

值得系统性吸收，重点不是增加更多角色口号，而是任务路由、完整专业参考、可复用资源和真实成果交付。当前 WorkDSH 技能创建器已借鉴真实例子→资源规划、编辑保护、范围与发布回执，但仍有两个重要短板：入口正文留在 TS；自然语言保存只支持 SKILL.md，不能完成脚本/模板/参考整包制作与导出。不能以 references 已存在就宣称与 WorkBuddy 整包制作等价。

本次只形成分析和实施建议，不安装技能、不改运行代码、不调整已发布作品、不承诺新业务模块全部开发。没有验证付费模型效果，专业效果评价是对方法与资源的判断，而不是 A/B 实测胜出。

## 全部顶层技能分类

“可吸收”指方法可用于现有系统，不表示无需修改即可执行。没有逐技能明确授权的文件不能据两份 Apache 许可证推断整个目录均可再分发；Internal 标签的内容作为设计参考。许可元数据不等于远端服务访问授权。

| --- | --- | --- |
| skill-creator | 六阶段制作、四种组织模式、资源树、试用迭代、修改标记；路径与管理动作是 CodeBuddy 特定 | 优先增强现有创建器，保留原生 Harness Skill 运行 |

嵌套的 shared-styles、design-variables、component-instance 是 ardot-design-core 的子能力参考，不应作为三套独立专家或重复全局入口。

## 技能创建器：为什么好，哪里不能照搬

### 六阶段的具体价值

1. 从实际请求与输出例子定义能力，而不是给专家换个称号。明确正例、相似但不适用的请求、缺输入时的行为。
2. 从实际执行中找出值得复用的脚本、领域知识和素材；目录并非必需项，没必要的示例必须删除。
3. 初始化时给组织模式选择：顺序流程、操作任务集、规范参考、综合能力，允许混合，避免所有技能同一模板。
4. 面向下一位 Agent 写非显而易见的知识；资源有真实引用和读取条件。
5. 自动校验后交付 ZIP，用户拿到的是完整制品，而不只是聊天里的正文。
6. 用真实任务暴露问题，再修正指令/资源。市场安装技能编辑后 userModified 标记保护定制。

渐进加载值得保留：元数据用于发现，触发后读入口，详细资源按需读。不能把“脚本可不加载全文执行”误解成无限上下文或无需审查环境。

### 对比我方当前代码

`packages/plugins/skills/src/index.ts` 的 skillCreatorContent 仍是长 TS 模板字符串；resources/skill-creator 只有两份参考。它已经覆盖真实例子、资源选择、复用结构、任务状态更新、中断对账和发布回执，不需要全部推翻。

但 workdsh_save_skill_draft 仅携带 SKILL.md。创建器本身明确写着不能发布资源树。浏览器完整 bundle 导入不能等价为“AI能自然语言创建并交付完整 bundle”。下一步应补资源生命周期，而不只是把 WorkBuddy 正文再缩写进 TS。

WorkBuddy 的 agent_created 与市场 userModified 是其管理契约，不应直接成为我方权限依据。共享 `.agents` 与 profile 路径沿用已批准的 Harness 契约；workspace-only 目前没有该流程支持，不静默扩大范围。

### 隔离脚本检查的实际结果

只在临时目录运行 quick_validate.py 与 package_skill.py 的函数，没有调用 WorkBuddy 服务，没有安装到用户目录。样例 .env 仅含 DUMMY_ONLY 测试文字。

| 检查 | 实际结果 |
| --- | --- |
| 合法基础技能 | 通过 |
| 重复 name 键 | 被判为有效 |
| description 空值 | 被判为有效 |
| description 的 YAML 未闭合 | 被判为有效 |
| 正文引用不存在的 references/missing.md | 被判为有效 |
| 打包包含 .env 和 __pycache__/dummy.pyc | 均进入 ZIP |

原因：quick_validate 用正则与字符串检查，不是真实 YAML 解析，也没有资源引用验证；package_skill 递归打包全部文件，没有通用排除、文件清单和大小约束。SKILL 对校验的描述比当前脚本实际覆盖更多。脚本可参考接口，不适合未经改造直接作为我方发布验收。

## 网页、PPT 和文档：哪些专业内容应该保留

ardot-ui-design 将 landing-page、web-app、mobile-app、table 分开，不同产物的布局与交互标准不同。落地页先内容后视觉，表格关注可扫读和操作结构；不能只提炼成“精美、专业、现代”。设计转代码还有实现规则与网站样式提取的独立流程。

需要调整的内容也存在：landing-page 要求即使用户已给完整 brief 仍先强制问多选页面区块，并做模拟 superfan 访谈；这是产品流程，不适宜全局照搬。应使用已有信息，只补影响结果的缺口，模拟洞察不写成真实研究。Ardot 的“每页至少两件装饰”“不允许纯白/纯黑”与画布像素字号是其风格契约，不应对全部商业 PPT 强制。

ardot-slides 先定来源/受众/样式/页数，保存大纲，每页生成后检查，全局检查视觉节奏。这些适合现有 PPT。原文明确仅做 Ardot 设计，显式 PPTX 请求交给 pptx；我方用户要求最终 PPTX，所以应保留现有 PPT 编辑器与导出，不能把画布设计当成 PPT 交付。

tencent-docs-routing 的关键是精确分流：新建与修改、是否有源 Excel、确定地址的操作与需理解数据的任务分开。其路由引用 tencent-pptx、tencent-docx、tencent-docs-sheet-generation、tencent-docs-sheetagent，但这四份完整实现不在本目录。tencent-local-office-edit 的 edsdk.py 是本地 MCP 客户端，依赖真实服务，不是自带编辑器。

HTML 研报规范明确要求 node --check、使用固定 ECharts option 骨架、图表真实渲染才完成；这些能减少脚本错误。但示例依赖 CDN，JS语法通过不能证明 CSS 生效、容器有宽度、iframe 资源允许、离线可用。之前网页样式丢失应联合检查生成规则和预览运行条件，不能仅归责 Skill。

品牌/系列图参考的锚点链很强：真实参考产物+固定不变量+角色名+派生关系，比每张独立文字提示可靠。适配时保留专业细节，生成工具与成果引用换成我方真实公开契约。

## 我方建议实施顺序（未开始实施）

### 第一项：增强现有 Skill 创建器

- 建立 resources/skill-creator/SKILL.md 为唯一正文源，TS只注册或单向构建导出，保留现有调用兼容。
- 保留 WorkBuddy 六阶段完整制作方法与资源组织选择；按需拆创建、编辑、资源、校验/交付参考，不添加空文件装饰。
- 在现有 SkillManager/CAS/校验/Host身份基础上补完整资源保存、预检与受控安装，不新增 Skill registry 或执行器。
- 资源处理覆盖文档、脚本、模板/二进制及文件清单，控制路径、大小、覆盖与依赖；专业脚本需要托管运行环境或明确可用环境，不能假设 Desktop 用户有 Python。
- 新增真实整包下载/交付回执，保存、安装、试用成功、导出成功分别报告。
- 用户定制保护使用我方来源/修订与冲突信息，不伪造第三方 metadata。

验收：通过创建入口自然语言制作含真实 reference、脚本与模板的通用技能；在隔离官方 Profile 安装后读取/运行资源；编辑保留未改文件；重启仍可用；ZIP导出/再导入字节与引用保持；缺资源/依赖、路径越界和覆盖冲突真实拒绝。至少一个典型请求、一个不适用请求、一个缺输入情形。没有托管 Python 时不以开发者机器上的成功代替 Desktop 发布验收。

### 第二项：补专业网页/Office参考，而非换编辑器

将对应任务的完整专业方法映射到现有 workdsh-web/ppt/word/excel-design。先确定请求→技能→真实工具→产物的路由；先展示并渐进更新已有作品，不反复创建。验收需检查实际渲染、保存重开和最终文件。参考许可逐文件记录，未明确可再分发时形成我方规范。

### 后续项

推荐专家/连接器、市场安装、资料库、云发布与媒体生成按用户路线后置。先有真实 Host/provider/账号/工具和错误契约，再启用相应技能。wb-finance-skill 可作为公共可选领域能力配给相关专家，不为当前一个专家专门硬编码，更不无条件加载所有金融 references。

## 边界和复用记录

本次复用面是分析已有文档和现有 WorkDSH 注册/生命周期工具，不引入框架。官方底座继续拥有 Skill解析/发现、Session、工具执行、沙箱和 watcher；我方只补制作对象、资源修订、权限、发布和交付。26个入口完成结构盘点，重点深入阅读创建器全文/三个脚本、Office路由与编辑契约、设计/PPT/系列一致性和资料库变更/内容契约；不是声称286份资源逐行审计或所有计算算法验证。

未执行：原始专家/金融全套脚本测试、腾讯服务端接口验证、付费模型对比、技能安装、生产发布。没有因为 skill 名称或提示词优秀而认定工具已可用。
