# 资料库 0.1 开发计划

日期：2026-09-16。模块：`workdsh-plugin-library`。主任务：D06 / P1-06。

## 1. 目标

第一版交付一个本地资料闭环：用目录树管理资料，导入文件并保留原件，把内容确定性转换为统一 Markdown，在对话中显式引用，把任务成果保存回资料库，修改后形成新修订。页面、Agent 工具和后续项目插件统一调用资料库领域服务，不分别保存另一份正式资产。

产品定位参考 WorkBuddy 官方资料库，但第一版不照搬其云端协作能力。资料库首先是“人和 Agent 共同持续使用的产物空间”，检索只是其中一项能力。完整闭环是：资料进入目录树 → 添加到任务 → Agent 读取或修改 → 成果保存回资料库 → 后续任务继续使用。

支持范围：

- Markdown：`.md`、`.markdown`。
- 纯文本：`.txt`，首版支持 UTF-8，其他编码给出明确错误。
- PDF：文本型 `.pdf`；保留原件并提取页码和正文。扫描件 OCR 暂缓。
- Word：`.docx`；保留原件并提取段落、标题和表格文字。旧二进制 `.doc` 暂缓。
- PowerPoint：`.pptx`；保留原件并按幻灯片提取标题、正文、备注和表格文字。旧二进制 `.ppt` 暂缓。

首版不承诺复杂版式还原、图片文字识别、网页抓取、CSV/HTML 原生应用、公开链接发布、向量数据库、团队共享、公共资料市场或多人服务器部署。

## 2. 当前存储决定

现阶段存储在用户本机，属于可信本地用户版本：

- 元数据和权限引用通过 Harness `storage-domain` 保存。
- 原始文件、不可变修订 Markdown 和转换元数据保存在 `DSH_HOME` 下由资料库插件管理的目录，建议逻辑位置为 `$DSH_HOME/library/`。
- 搜索索引是可重建缓存，不是唯一正文来源；损坏后从修订重新生成。
- 每个原件和正文修订记录 SHA-256。升级插件不覆盖用户资料，卸载插件默认保留数据。
- 浏览器只持有业务 ID 和上传回执，不获得或拼接 Host 文件路径。

未来团队版由 `packages/providers/library-team` 提供共享存储实现，但必须遵守相同资产与修订契约。本地 0.1 不提前依赖团队服务。

## 3. 核心对象

| 对象 | 作用 |
| --- | --- |
| `Asset` | 一份资料的稳定身份、名称、类型、归属、状态和当前修订。 |
| `AssetRevision` | 不可变版本，记录原件哈希、派生 Markdown 哈希、来源、创建者和时间。 |
| `AssetSource` | 上传、任务成果或未来连接器来源；不保存凭据明文。 |
| `AssetReference` | 对话、项目或其他对象对固定 `assetId + revisionId` 的引用。 |
| `AssetDraft` | 尚未发布的修改及其基线修订，用于差异审阅和并发冲突检查。 |
| `LibraryNode` | 目录树节点，记录所属空间、父目录、排序、名称及关联资产；文件夹本身不伪装成资产。 |
| `LibrarySpace` | 资料归属边界。0.1 仅实现本地“我的资料”，为后续团队空间保留稳定标识。 |

删除、停用和撤权不会修改历史任务记录，但会阻止再次读取正文。任务必须固定修订，不能在运行中静默切换到最新版。

## 4. 技术边界

- Harness 继续拥有 Session、Conversation、Attachment/File Upload、权限预设和运行事实。
- Library 拥有正式资产、修订、来源、索引、检索结果和入库回执。
- Office 拥有 DOCX/PPTX/PDF 的预览或编辑工作副本；工作副本不是正式资产。用户发布后由 Library 生成新修订。
- 项目插件以后只保存资料引用，不建立项目专属文件存储。
- `deliverables/presented` 只是任务交付事实；必须经过 `registerDeliverable` 校验并返回 `AssetRevision` 才算入库。

所有格式先通过资料库内部的只读 converter 转成统一 Markdown。转换是确定性本地代码，不调用模型：

| 输入 | 首版转换方式 | Markdown 结构 |
| --- | --- | --- |
| Markdown | 规范换行、编码和安全元数据，正文不重写 | 保留原有标题、列表、表格和代码块 |
| TXT | UTF-8 解码并转义会破坏结构的内容 | 作为普通段落，保留空行 |
| PDF | 复用已审查的 `pdfjs-dist` 读取每页文本 | `## 第 N 页` 加页面正文；记录页码锚点 |
| DOCX | 抽取现有 Office DOCX importer 的纯解析能力，基于 `JSZip`/OOXML | 标题、段落、列表和 Markdown 表格；图片/复杂对象保留占位及警告 |
| PPTX | 复用现有 `pptx-viewer-core`/OOXML 读取幻灯片元素 | `## 第 N 页：标题`，正文、备注和表格；图片/图表记录占位及警告 |

转换结果统一保存为 `content.md`，另存 `conversion.json` 记录格式、转换器版本、页/段/幻灯片位置、警告和原件哈希。搜索和 AI 默认读取 Markdown；下载、预览、再次转换和格式核验始终使用原文件。Markdown 是派生阅读视图，不替代原文件，也不承诺完整还原视觉版式。

解析器实现应从 Office 中提取可共享的无状态转换模块或通过公共转换契约复用，不能让 Library 私下导入 Office 插件内部类。Office 继续负责编辑器和预览；Library 只做只读转换和正式资产修订。转换失败不影响原件安全落盘，但该修订标记为“转换失败/不可搜索”，不能伪装成功。

## 5. 开发切片

| 切片 | 工作 | 退出条件 |
| --- | --- | --- |
| L0 契约与存储 | 增加 `workdsh-contracts/library`；实现 Space、Node、Asset、Revision、Draft、Reference；本地目录、原子写入、哈希、配额和恢复 | 文件夹创建/移动/重命名与资产创建/读取/冲突/越权/重启测试通过；索引删除后可重建 |
| L1 导入与转换 | 复用已验证的认证流式上传；支持 MD/TXT/PDF/DOCX/PPTX；生成统一 `content.md` 与 `conversion.json`；目录树、详情、来源、当前修订和转换状态 | 五类真实样本导入指定目录并回读原件；Markdown 结构和位置可复核；超限、伪类型、压缩炸弹、路径逃逸和取消被拒绝 |
| L2 检索 | 标题和正文关键词检索；中文/英文基础切词；类型、来源、时间过滤；返回带页码/段落/幻灯片的片段 | 命中内容、来源、位置和 revisionId 可复核；无权资料不进入结果 |
| L3 对话引用 | 在官方输入来源中贡献 `@资料库`；可选择一个文件或目录；显示资料名称；提交固定修订引用；提供 `library_search`、`library_read` | 新会话默认不选资料；显式选择后模型只读授权修订；目录引用展开为有界清单；撤权和停用即时生效 |
| L4 成果回存 | 提供“添加到任务”和“保存到资料库”；实现 `library_create_draft`、`library_update_draft`、`library_publish_revision`、`registerDeliverable` | 原文件/目录能派入任务；任务成果能选择目录并获得正式入库回执；重复 operationId 幂等；失败不产生半条资产 |
| L5 修改审阅 | 文本差异、基线修订、用户确认发布；可选调用 Office 工作副本编辑 DOCX/PPTX | 并发修改显示冲突；未确认草稿不替换当前修订；发布后可再次检索 |
| L6 生命周期与交付 | Client/Host/工具注销、冷启动、升级、卸载保留、独立打包和项目组合安装 | build/typecheck/测试、两次冷启动、卸载重装、`.tgz` 安装和真实模型闭环通过 |

L0 到 L6 顺序执行。L1 可以并行准备各格式样本，但 L2 不在修订与权限模型稳定前开始。

## 6. 页面与交互

资料库页面第一版采用“导航 + 目录树 + 原内容工作区”，而不是以扁平搜索结果列表作为首页：

1. 左侧一级入口为“搜索”“最近”“本地产物”；主体为本地“我的资料”目录树。
2. 目录树支持新建 Markdown、新建纯文本、新建文件夹、上传/导入、展开折叠、重命名、移动和删除。
3. 文件菜单支持“添加到任务”；复制的是稳定的资料引用，不泄露本机绝对路径。团队邀请、分享和公开链接暂不出现。
4. 中间工作区打开原始内容：MD/TXT 可编辑；PDF 先只读预览；DOCX/PPTX 交给现有 Office 能力预览或编辑。派生 `content.md` 是隐藏的检索视图，不在目录树里制造重复文件。
5. 搜索结果显示名称、类型、所在目录、来源、更新时间、修订、转换状态及页码/段落/幻灯片命中位置，并可跳回原内容。
6. 对话通过 `@资料库` 或选择器添加一个文件或目录；输入框显示所选资料名称或类型图标，默认不选中任何资料。
7. 任务成果提供“保存到资料库”，用户选择目标目录；已有资料修改提供差异审阅和“发布新版本”。

转换中、转换失败、已停用、无权限和修订冲突必须是不同状态，不能统一显示“失败”。

## 7. Agent 工具

| 工具 | 用途 |
| --- | --- |
| `library_search` | 搜索当前主体有权读取的资料，返回片段、位置和固定修订引用。 |
| `library_read` | 分页读取指定修订，重新校验权限和大小限制。 |
| `library_create_draft` | 从文本或任务成果创建待审草稿。 |
| `library_update_draft` | 使用 expectedRevision 修改草稿，拒绝静默覆盖。 |
| `library_publish_revision` | 用户确认后发布不可变修订。 |
| `library_register_deliverable` | 校验真实任务成果并幂等登记为资料修订。 |

工具返回规范 JSON 业务回执；Client 另做可读展示。工具、页面和未来项目插件必须复用同一服务及授权检查。

## 8. 验收主链

1. 导入一份 Markdown 规则、一份 TXT 记录、一份文本 PDF、一份 DOCX 和一份 PPTX。
2. 检查原件哈希、派生 Markdown、转换状态、页码/段落/幻灯片位置和当前修订。
3. 搜索一个只出现在正文中的词，五类格式均能定位准确来源。
4. 在新会话中显式选择一份资料，模型搜索并读取固定修订，回答附来源。
5. 会话运行中撤销读取权限，再次读取被拒绝。
6. 模型生成 Markdown 报告并保存到资料库，取得入库回执。
7. 从另一会话搜索该报告，创建修改草稿，审阅差异并发布新修订。
8. 验证旧会话仍引用旧修订，新会话可选择新修订。
9. 冷重启 Host，资料、修订、索引和引用仍一致。
10. 验证重复导入、同 operationId 重试、损坏 PDF、恶意 DOCX/PPTX、超限文件、取消、并发发布和插件卸载。
11. 将一个目录添加到任务，确认只展开当前用户可读、在数量和总字节限制内的固定修订；超限时要求缩小选择范围。
12. 从任务保存一份 Markdown 到指定目录，重启后仍能在目录树和“最近”中打开，并可被下一任务再次引用。

## 9. 版本与交付

- 首个可安装包：`workdsh-plugin-library@0.1.0-alpha.1`。
- 只在实际代码开始时把 `docs/modules.json` 的资料库状态改为实施中，并建立 package manifest；计划文档本身不代表功能完成。
- Alpha.1 必须提供独立 `.tgz`、SHA-256、manifest、安装说明、迁移/卸载边界和真实样本证据。
- 本地数据 schema 单独维护 `schemaVersion`；插件包升级不得覆盖用户资产。

## 10. 后续版本

- Alpha.2：图片和扫描 PDF OCR、语义/向量检索与混合排序。
- Alpha.3：网页及连接器资料同步、刷新策略和来源失效诊断。
- 内容应用版：原生 CSV 表格与 HTML 页面，建立 MD（内容）、CSV（数据）、HTML（呈现）的引用关系；不把它们塞进首个文件资料版本。
- 协作与发布版：MD 修订建议/回退、评论、团队空间、成员权限、公开链接发布；权限与 Agent 读取范围使用同一授权判断。
- 团队版存储：接入 `provider-library-team`，重新验收组织隔离、成员撤权、并发和审计留存。
- 项目版联调：项目资产页只显示经过授权过滤的 Library 引用，并完成成果入库后关联。
