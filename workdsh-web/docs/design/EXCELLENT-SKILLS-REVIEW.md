## 腾讯 PPT：把设计判断做成可执行工作方法

已阅读 SKILL.md、create-from-scratch.md、story-principle.md 与 design-principle.md 的重点段落，并核对组件资源目录。入口约 1552 字符，22 份 Markdown 参考：它正是短入口承载多分支知识的良好例子。

值得复用的五点：

1. **先定义表达目标**：受众、希望观众记住或采取什么行动、页数、调性与内容边界。不是直接把材料拆成标题列表。
2. **每页有叙事职责**：页面角色、版式、核心视觉、密度和结论共同规划；重要数据配事实支持的解释，避免数字孤立。
3. **视觉系统具体化**：画布区域、颜色、字号、字重、间距及页脚位置明确；制造主次尺度差异，避免所有元素大小接近。
4. **整份演示有节奏**：封面、重点页、信息页和行动页承担不同作用；图表和图片用于表达内容，减少重复卡片排布。
5. **过程面向用户，结果可校验**：用内容大纲、风格设计、逐页制作等语言沟通，及时打开预览；提交前自检，完成后按工具返回修复。

适配到本项目时保留这些判断标准，使用原生可编辑文本、图表及现有 ContentService/CAS/导出。1280×720、特定视觉占比、Hero 配额、STORY.md/DESIGN.md、.slide DSL、slidep-start/validate 和后续编辑专用 Skill 是原环境约定，不强制移植。短三页日报不需要为满足配额增加章节或无依据的数据。当前原生导出有文件卡流程，不需另一套构建管线。

## ppt-implement：结构化生产与可复用版式

入口约 38272 字符，8 份 Markdown 参考。重点阅读素材、章节、视觉系统、页面检查、修改范围及输出/导出段落。

值得借鉴：不同演示类型采用不同叙事结构；页面规划包含用途、密度、视觉和模板选择；局部修改与整体换风格分开处理；截图检查成为交付流程的一部分。

迁移需要调整：网页模板目录和 CloudStudio 环境不适用于当前项目；广泛生成 PPT 触发与当前原生流程重叠。固定 14–20 页、每页字数/数据点配额不能覆盖用户页数和事实约束。输出规则写已生成 presentation.pptx，与另行请求才执行导出的段落不能直接充当真实文件回执。将视觉方法作为参考，不能让此技能重新建立第二套默认 PPT 引擎。原指令中的并行页面生产只是原流程说明，本轮未调用或实施。

## Skill Creator：把经验封装成可复用能力

市场副本约 2177 字符，2 份参考和 3 个脚本；Codex system 入口约 15311 字符。长短不同不能自动排列优劣，应看是否提供目标环境所需知识。

共同值得复用：从真实使用例子反推触发场景；识别经常重写的操作并做成脚本；将说明、参考和产物素材分别组织；使用输入/输出例子表达品质；校验后交付，再依据真实失败迭代。

更具体的收获：

- 触发描述说清实际能力，而不是吸引所有相关主题。
- 入口只包含共同目的、必要约束和引用路由；简单技能不必强行拆文件。
- 严格接口、脆弱转换步骤适合确定性脚本；开放设计保留判断空间。
- 创建、编辑、发布分开；修改用户安装副本应有来源与防覆盖策略。
- 校验器必须匹配宿主允许的元数据。市场 quick_validate.py 有字段白名单，不能直接作为 Harness 的权威解析器；WorkBuddy 的 agent_created/userModified 标记也不是本项目权限依据。

## 对 WorkDSH 整体的整理原则

| 层次 | 负责什么 | 验收关注 |
| --- | --- | --- |
| Skill | 专业方法、目标场景、参考与确定性辅助 | 是否选对、资源是否能用、真实任务是否改善 |
| 专家 | 领域判断、配备能力、边界和完整交付职责 | 事实正确、必要追问、可用成果 |
| 工具/业务服务 | 操作契约、授权、修订、持久化和真实回执 | 数据正确、冲突/拒绝处理、文件可用 |
| 平台/Harness | 官方能力发现、任务执行和日志 | 不重复造加载器或执行器 |

本轮建议是保存并学习优秀技能，不按长度批量删改。质量工具应提示人工审阅；长入口可能有合理协议或环境约束，短入口也可能丢失关键流程。后续选择几类真实任务比较成品和工具回执，再决定是否拆分引用或调整描述。
