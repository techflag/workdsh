当前阶段：D04 / P1-02，专家模块 0.1。本文是开发任务清单；初始清单不代表当前状态，实际已执行项见 STATUS 和 D04 evidence。本轮新增 AT-24～27、AT-T05～T07 均为 **未执行**。历史 Skill/治理测试不能替代专家验收。

## 1. 编码前必须通过的有限关卡

新增复核：[插件交付边界](PLUGIN-DELIVERY-REVIEW.md)。并入 EP-01/G05 与 EP-07/AT-20，验证专家的标准 Host/Client 入口、独立配置行/子 Fiber、可安装制品和独立移除；不新增业务阶段。

| 关卡 | 可重复探针 | 通过标准 / 失败处理 |
|---|---|---|
| G01 角色组合 | npm published exports 编译；A/B preset/persona；空变量、字面大括号、complete/runtime flags；重启 | 两 Session 角色不串、原生上下文保留；确定只读构件生成途径。失败只研究该公开 seam，不下载上游实现 |
| G02 声明 Skill 依赖 | 公共快照契约最小实现；同名目录/正文/资源；编辑、停用、卸载、重启 | 快照可追溯、动态全局 Skill 仍可用、依赖坏掉不回退同名全局；失败不得标 REQ-EXP-007 完成 |
| G03 运行绑定全路径 | 原生 prompt/resume、刷新、冷启动、fork、空会话换 preset，篡改/删除构件 | 所有受管 Session 执行前校验固定绑定；未绑定普通任务不受影响；不能靠专用按钮路径通过 |
| G04 原生创建与草稿 | create 指定 sessionId/agentPreset + model selection + input overlay；切页、重复挂载、用户已有草稿 | 一次交接到正确 Session，/ @ 附件等可用，无自动发送，不重复建任务 |
| G05 传输 | 专家最小 Typert Remote 生成、认证、错误、取消、dispose、打包 | 成功则使用 Typert；失败须复现并记录专家独立 Connection exact Fetch 例外，不静默自造通道 |
| G06 持久与恢复 | Domain CAS、提交前后 kill、丢响应、审计汇出失败、断线重试 | 已提交事实可对账，未提交不被发现，同键不重复发布/建任务；不宣称跨域事务 |

复用已有证据可缩小探针，但必须说明覆盖哪条、哪些是本次新增。以上是边界验证，不是要求把整个 Harness 重新测一遍；发生失败时记录准确 error/export/version，提供一个有限替代，无法满足核心语义才阻断相应能力。

## 4. 测试层次与交付命令

契约/领域测试覆盖状态、CAS、确认、幂等和输入校验；官方 Host 集成覆盖组合与持久性；真实打包 Web 覆盖输入框/导航/弹框/重连。假数据只可用于测试 fixture，不进入生产目录。模型可重复 stub 验证 prompt 和工具路径，另用一次经授权的低风险真实调用证明专家/Skill 的 end-to-end 路径；报告清楚区分两种证据。测试输出隐藏凭据，不用用户真实任务作为破坏性样本。

遵循根 package.json 的现有 scripts；新增专家脚本应在实现阶段登记。当前已有基础检查：

```sh
corepack pnpm install --frozen-lockfile
corepack pnpm check:plan
corepack pnpm test:planning
corepack pnpm check:versions
corepack pnpm typecheck
corepack pnpm build
```

使用仓库要求的 Node/pnpm 版本；这些命令不自动打开图形程序。浏览器和运行探针按仓库既有 evidence 命令执行，不能把未知的 `pnpm test:experts` 写成已存在命令。新增组件/Host 后把测试接入根实际运行路径，证明不是只生成测试文件。

## 5. 交接检查与有限完成标准

开发前：确认当前 HEAD、目录规则、版本锁；阅读公开 docs/exports/types，不读上游实现填空。开发中每个 EP 有变更、测试和风险记录；接口缺口反写本包，不把假设当事实推进。

D04 完成必须同时具备：用户看得见的创建→发布→召唤→实际执行→重启恢复闭环；更新/启停/归档/导入闭环；全部 AT-01～AT-27；官方复用记录；真实打包截图；模块 0.1 和 bundle 的正确版本记录；已知限制公开且没有核心功能被假按钮替代。团队 AT-T 项不作为 D04 完成前置。

没有通过的项在最终说明逐项列出。完成后将 experts 标为 implemented 并按仓库台账推进；**本次只交付文档，不改当前 D04 的 todo 状态、不递增包版本。** 企业管理 Web、公共分类/分发、市场数据、团队后续模式各自另立明确范围，不能成为无止境“下一步”。
