## 1. 产品决策与现状

- Skill 是能力；专家是能力加领域经验、专业判断与整体交付职责；专家团是多位专家加 SOP 协作流程。
- 专家详情属于使用入口，编辑器属于管理入口。两者分开验收，缩小弹框或增加头像不能代替业务闭环。
- 已有专家草稿/确认发布/固定 Skill 修订/原生召唤、独立插件打包和两次冷重启证据；46 项集成通过。确定性适配器验证官方 Agent Loop 中 persona 与冻结 Skill，不等同真实远程模型或整份发布 preset 的 Loader 执行。
- 真实技能选择已替换手填名称；专业交付仍缺少完整业务证据等缺口；生命周期、关联交接、故障恢复等原有未完成项继续保留，不能因本轮产品修订删除。
- D04 / P1-02 继续为专家模块 0.1；下面 A～E 只是工作切片，不是五个产品版本。D11 为后续团队功能，本轮不启动代码开发。团队沿用专家插件的多对象组合归属；D11 开始时按模块版本规则登记实际交付线，不现在指定 0.2，也不创建每专家/每成员 npm 包。
- 公共运营、组织发布、服务器端及企业管理 Web 留在既有企业 ToDo；当前使用默认与个人对象，不增加 SkillHub、套件或虚构公共技能。

## 3. 场景与质量判定

| 场景 | 输入 | 必须行为与交付 | 不通过情形 |
|---|---|---|---|
| 正常分析 | 门店三个月合成销量/客流/转化/客单价；基准计算可复核 | 核对口径、拆解指标、真实技能计算，生成可打开的分析成果与管理摘要，数字匹配基准 | 仅泛泛建议、关键数字错误、没有承诺的实际成果 |
| 信息不足 | 只有销量下降百分比，无明细或关键指标 | 指明缺口、必要追问或给有标注的待验证分析方案 | 编造客流/转化数据或认定因果 |
| 数据质量问题 | 含重复、空值、单位及周期不一致 | 识别问题、明确处理方法与影响，不悄悄篡改原件，成果可回溯 | 错误口径进入结论且无说明 |
| 技能不可用 | 必需技能停用、缺失或冻结构件损坏 | 具体阻断与修复提示；既有原生普通任务不受错误回退影响 | 退回同名动态源、假装读取文件或假成果 |

三份正常/异常样本完成可重复检查；真实模型至少一次正常场景端到端，报告模型/版本、工具调用、成果引用、数字校验和人工评审。异常路径可用确定性测试补覆盖，不能宣称四条都已真实模型测试。真实调用与样本不得包含用户凭据或敏感数据；是否有可用模型/技能必须事前诊断，无配置则该验收保持未执行。不要为演示自动购买、配置账号或对外发布。

## 5. 技术约束与职责

| 所有者 | 职责 | 禁止做法 |
|---|---|---|
| Experts Host | 专家/团队业务定义、修订、校验、授权、绑定与委派关联；页面/管理工具同一服务 | 新建 Agent loop/loader/模型路由；一个万能平台核心 |
| Skills Host | 目录、完整内容/资源、修订保留与影响诊断；通过公开服务供专家引用 | 专家直接查 Skill 内部表、复制技能实现；仅凭名字挑首个匹配 |
| Harness | Profile/Loader/Cordis、preset/persona、原生 Session/Conversation、Skill 执行、subagent/workflow公开能力 | 修改上游源码、第二套权威执行状态和聊天流 |
| 公共 UI | Modal、基础选择/列表/反馈展示；领域组件组合使用 | UI 持有身份凭据、数据库或执行器；复制弹框外壳 |

现有 ExpertDefinition 的 role/methodology/boundaries/deliverables 可先承载专业经验，不立即添加万能知识库或虚构能力字段。需要结构化经验/领域字段时先统一 schema、契约、导入导出、迁移及摘要，不只改 UI。技能选择展示名称，保存当前契约允许的稳定 skillId+name；Host 发布时唯一解析并冻结修订，失效不自动替换。

团队 SOP 的阶段、成员引用、依赖、输入输出、评审与反馈须进入不可变修订；动态计划只记录业务计划及原生执行关联，不取代官方运行事实。所有资料访问和外部写入按发起主体最新权限处理，主持人/专业经验不能扩大权限。
