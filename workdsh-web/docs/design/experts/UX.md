# 专家界面、制作流程与公共组件规范

基线：PRD 1.1。以下尺寸与布局为 WorkDSH 设计建议；参考图用于交互和信息层级，不要求复制第三方素材。

2026-09-13 使用信息层级补充：详情与发布预览共享只读工作摘要，简介后优先显示“会交付什么、怎么处理你的任务、使用前需要了解”，分别来自现有 deliverables/methodology/boundaries。专业角色仍可展开，避免与工作摘要重复；示例和实际配备技能继续保留。内容不由模型生成摘要，不新增业务字段或状态真源。官方复用记录：沿用已验证的专家 Client 和公共 Modal，原生 conversation.input.overlay/inputActions 草稿交接保持不变；没有新增 Slot、Session 或发布接口。对应 A/C、AT-24/26，安装态探针验证发布预览、移动端和原生召唤。

## 1. 页面与入口

继续使用工作台“专家 · 技能 · 连接器”能力中心入口；进入后“专家”激活。保留原生工作区和会话树、重命名、归档、新建、设置及折叠行为。不在原生会话侧栏再重复新增一套能力中心按钮。

专家页面顶部：专家/技能/连接器导航、搜索、`我的专家 n`、`制作专家`。当前未开放的领域沿用真实能力可用性策略，不因本设计新增假入口。

- 专家中心：默认模板与已发布个人专家；来源明确，可通过“默认/我的”过滤。
- 我的专家：草稿、已发布、已停用、已归档筛选；草稿卡显示“继续编辑”，可用专家显示召唤与管理菜单。
- 分类模型保留。存在真实分类才展示分类条，未分类可检索；无分类数据时仅显示目录，不显示无效按钮。
- 目录数与搜索结果数分开；切换“我的专家”应改变标题、列表范围和可用操作，不能只是重复展示原页。
- 团队能力未交付时不显示可召唤团队卡。开发预览中的团队页面必须明确标识设计稿，不混入产品。

卡片建议 280px 以上、16px 间距、24px 内边距；头像 44～48px，标题一行截断带可访问完整名称，描述最多三行。宽度足够时四列，逐步降至一列，不固定四列造成溢出。

## 2. 图 1：专家详情

参考：[专家详情原图](references/expert-detail.png)。结构：

```text
[头像]  专家完整名称                              [关闭]
        来源 · 版本 · 当前状态
        [召唤专家] [⋯ 仅有权限的管理操作]

完整描述（较长时展开）
[标签] [标签]

专家帮你做
[示例任务一                                  对话图标]
[示例任务二                                  对话图标]

配备技能 n（真实名称、简介、可用/缺失状态；点击查看）
专业设定（经验、方法、边界、成果标准，可展开）
```

- 使用详情 max-width 800px，宽度 `min(800px, viewport - 56px)`，高度不超过 `min(820px, viewport - 80px)`；内容区纵向滚动，关闭按钮始终可达。≤600px 时全屏面板，动作可换行。
- 头像建议 72～88px，不占据半屏；名称完整换行，版本与来源采用次级文本。大标题与输入控件按 WorkDSH 公共字号令牌，不照搬截图像素。
- 没有统计服务就省略用量；不显示 `0 次使用` 暗示有统计，也不复制第三方发布者。
- 默认模板主操作为“召唤专家”，菜单为“复制到我的专家”；个人可编辑对象菜单含编辑、复制、停用/启用、归档。草稿无召唤按钮。
- 每条示例是实际按钮，有清晰焦点。点击准备指定示例草稿，不自动发送；原草稿已有内容则出现替换/取消选择，不静默覆盖。
- 缺失 Skill 显示名称及修复入口；未建设的连接/资料能力显示具体原因，必需项不满足时阻止召唤。

## 3. 图 2：专家团详情（D11）

参考：[专家团原图](references/team-detail.png)。复用同一 Modal 与 DetailHeader，顺序：头像/名称/召唤团队 → 描述/示例 → 使用案例（若存在）→ 团队成员 → 协作方式/资源约束。

成员卡显示头像、角色名、专家名和版本、主持人标识；主持人唯一。点击成员打开其详情的同一面板子视图并提供返回，优先避免多层 Modal。案例只有真实内容和有效链接才显示，不放截图里的案例充数。

创建任务后显示团队任务摘要：主持人、成员状态、当前阶段、已完成/失败数、真实子任务链接、取消和汇总。团队模式不是用一个 spinner 隐藏所有成员。执行状态和取消说明见 [专家团方案](EXPERT-TEAMS.md)。

## 4. 图 3：制作专家进入任务框

参考：[制作专家原图](references/create-expert.png)。点击“制作专家”后进入工作台的新任务位置，使用原生 Conversation。默认引导文本固定为：

```text
/expert-manager 帮我创建一个 XXX 专家，擅长 XXXXX。我的经验是：[请补充你的行业背景、相关经验]
```

`expert-manager` 必须由官方 Skill 发现与输入触发链路识别；展示为原生支持的标记/chip。若锁定版只支持指令高亮，接受原生表现，不插入伪造 DOM 胶囊。未发现管理技能时提供明确错误，不加载无法执行的假标记。

草稿要求：

1. 绑定此次目标 Session；待组件挂载后一次性应用，校验目标 Session 和原草稿版本。
2. 用户已写内容时不能覆盖。刷新/切页重复挂载不再次写入，不在其他会话消费。
3. 用户点击发送前没有模型请求。`/`、`@`、附件、权限、模型、推理强度与发送按钮保持原生功能。
4. 创建向导先询问缺失信息，可从现有 Skill 选择真实能力；禁止自动安装推荐技能。
5. 对话产出结构化草稿，提供“查看草稿”卡片；不是只回复一段没有落库的 JSON。
6. 发布前展示名称、角色说明、方法、边界、交付、Skill 依赖和差异。按钮“确认发布此版本”对应精确内容；发布后展示“去试试”“返回我的专家”。

## 5. 专家草稿编辑

同一编辑面板提供基本信息、专业角色与方法、交付要求、能力依赖、示例任务五组内容。基础字段可表单编辑，长说明使用正文编辑器；完整原始数据仅作可选高级查看，不把内部 preset YAML 交给用户编辑。

名称 1～80 字；简介 1～300 字；单段角色、方法、边界或交付不超过 16,000 字，四段合计不超过 32KiB UTF-8；标签≤8，每项≤20 字；示例≤6，每项≤2,000 字。允许先保存不完整草稿，发布时强校验；超限保存须明确字段错误，不能截断。限制属于当前设计默认值，调整需同步导入校验与测试。

保存显示已保存时间。并发冲突保留本地内容，展示最新版本与差异，可复制本地内容或重新加载；不自动合并专业规则。离开未保存内容时给出继续编辑/放弃修改。失败不能把按钮改成“已保存”。

## 6. 状态与反馈

| 状态 | 界面行为 |
|---|---|
| 首次加载 | 骨架与可访问加载状态；不闪现空目录 |
| 空个人目录 | “还没有自己的专家”，提供制作和浏览默认模板 |
| 搜索无结果 | 保留查询，允许清除；不能混同服务错误 |
| Host/插件不可用 | 错误原因、重试；取消只影响当前请求 |
| 发布中 | 禁止重复提交；关闭后仍可通过操作记录核对结果 |
| 超时/断线 | “结果待确认”，按操作编号查询；不立即提示失败并重试创建 |
| 专家停用/归档 | 可查看历史；新召唤和下一次使用明确被阻止 |
| 编辑冲突 | 保留草稿并展示处理选项 |
| 已删除的依赖 | 显示具体依赖；修复需新修订，不能偷偷改当前绑定 |

## 7. 公共组件和代码边界

复用现有 `workdsh-ui` 的 `Modal`、`Icon`、导航与 tokens。拟新增可复用 `DetailHeader`、`PromptExampleList`、`StatusNotice`、`ConfirmActionDialog`，只在确有第二消费方或稳定公共语义时提升到 UI 包；专家字段和服务调用留在专家插件。

组件用 `.tsx`，`index.ts`/`client.ts` 仅导出与装配；不在入口堆叠 `h('div', …)`、HTML 字符串或业务 CSS。Props 传数据和回调，组件不直接访问 Cordis Context、fetch 或文件系统。优先现有令牌；新增 CSS Modules 支持需先验证打包，不凭空假设配置已有。

现有 Modal 是可用外壳但未承诺所有新场景：未保存关闭拦截、嵌套焦点、菜单越界、弹框内二次确认必须单独验证。禁止另写一套专家专用遮罩来绕过公共组件缺口。

验收包含键盘、Escape、焦点回归、200% 缩放、长中文名称、暗/浅主题、窄屏和滚动。截图中任何可点元素都要有真实语义、错误反馈和回归场景。

## 7. 本轮补充：专家使用与编辑分离

对应 REQ-EXP-013～016。默认详情是使用页，不能直接展示大段可编辑 textarea、Skill 名称输入或“添加依赖”。顺序：专业头像/默认标记、身份名称、简介 → 擅长领域 → “试试这样问我”真实示例 → “配备技能 n”实际列表 → 可审阅的专业设定；召唤可位于头部或固定操作区，避免重复主操作。技能列表展示名称、简介与可用性，原始 ID/摘要收于次级信息；无显式技能时诚实说明，不将全局目录充当配备技能。

编辑只通过“编辑草稿”等管理操作进入，桌面宽度上限 760px，正文滚动、保存/发布操作可达，共用唯一关闭按钮。专业经验、方法、边界、成果可精细编辑；必要的专业背景由对话先澄清，不要求用户在空白表单中编写所有提示词。保存草稿不发布，发布前提供使用详情预览及技能实际状态，明确确认后才产生修订。

技能选择器属于领域组件，消费 Skills 公开服务：

1. 点击“添加技能”后显示可搜索的真实已安装目录，区分加载失败、空目录、无搜索结果。
2. 每项展示名称、简介、可用/停用/损坏状态；已选择项可识别，不允许重复添加。
3. 保存稳定对象引用，显示易懂名称；同名技能需要明确选择，不按第一个字符串匹配。
4. 关闭选择不改草稿；确认后加入草稿列表，移除只解除该专家配置，不卸载共享 Skill。
5. 已选技能后来不可用仍显示原因，发布/召唤按 Host 诊断阻断；不自动换技能、不自动安装。
6. 未实现选择器时仍记作缺口，不能把现有手填名称称作选择能力。基础 Modal 可共享，授权与引用解析由领域服务负责。

专家团详情除成员与主持人外，必须展示 SOP 摘要（谁先做、何时并行、输入输出和评审）。运行页面按原生事实显示成员任务、当前阶段、等待输入/审批、交接产物、失败或未执行项；单个 spinner 或最终汇总不能遮蔽实际成员执行。

## 草稿与使用详情的版本说明（2026-09-12）

详情展示已发布定义与其技能；可编辑用户的已保存草稿内容不同则提示尚未发布，展示已发布/草稿的技能数量并提供编辑入口。编辑器区分本地未保存、已保存草稿和确认发布，保存不更新已发布定义，已有任务不被重新绑定。扩展能力声明另列，不计入配备技能数量，尚无接入校验时明确显示暂不支持接入。

## 对话创建与发布前使用预览：C候选实现

制作专家仍进入原生任务框，草稿补目标/经验/预期成果；指南要求信息足够先起草，只追问影响判断的缺口，不虚构用户履历。模型可通过workdsh_expert_list_skills查询目标可编辑专家的真实目录，仍由同一Host鉴权。发布前预览使用已保存且与validate草稿修订一致的Host定义，完整展示简介、领域、六项以内示例、固定技能及完整专业设定；预览仅展示，不召唤/发送，取消回到草稿，摘要变化须重新预览。公共Modal外壳不重复实现，760px上限、820px高度与内部滚动、底部确认固定。真实对话内容质量归D场景验收，不从指南文案宣称通过。
