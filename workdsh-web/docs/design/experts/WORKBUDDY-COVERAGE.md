# WorkBuddy 专家制作与交付能力覆盖

用户明确要求完整覆盖 expert-manager 专家/专家团体系，不将原先未实施项作为永久范围排除。

| 能力 | 实现与验收 |
| --- | --- |
| 需求创建/资料转化/仓库转换 | 创建Skill按原规范提取内容，保留Agent/Skill/参考/脚本/模板 |
| 单体与团队制作、修改、批量维护 | 同一Host草稿服务、稳定标识、整包校验，批量逐作品串行保存/校验/注册 |
| 展示/头像/二进制与CLI | 原始字节保存、导入导出、发布固定和漂移核对；执行仍经原生沙箱 |
| 注册与整包交付 | 保存注册草稿中心、统一确认发布、完整包实际文件present |
| 单成员专业调用 | 顶层主理人选择固定成员，真实子Session回传完整输出，无强制额外评审 |
| SOP串行/并行及主理人中转 | 从Agent MD选择流程，执行计划支持可选评审；无依赖阶段可并行，后序接收完整前序输出 |
| 修改/撤权/取消/重启 | 旧修订不变、禁止替换/自派/成员直连，取消保留状态，不自动恢复执行 |

官方复用：锁定0.1.5-rc.1，使用现有公开subagent provider与AgentRegistry/AgentLoop，官方Session持久日志（session-query.md）、StorageDomain（storage.md）、SkillFilesystem（filesystem.md）。专家插件只补作品资源与业务编排，不修改上游、不另建Team执行器。现有TM-01 adapter/sop/integration/team探针保持回归。

验收逐项以代码和运行证据回填，不以规范存在宣称功能齐全；付费模型质量与视觉验收单列。

## 本次已接入与证据边界

- 完整正文与文件包：自由 Agent MD 为源，摘要字段只作兼容索引；较长原文按正文大小校验。成员姓名、职业与实际头像由原元数据映射，编辑保留包 name/agentName。
- 原资源安装与移植：save_resources 从绑定工作区读取原字节，bin 可执行标记随发布固定；原始 ZIP 与 WorkDSH 包可往返。包内脚本/模板/CLI 不自动安装依赖或绕过沙箱。
- 普通成员调用：team_ask 固定成员真实子 Session，完整输出回到主理人；不额外创建评审。原生探针检查真实专业 Skill、完整输出和冷进程恢复。
- 协作计划：主理人按完整正文形成 team_open 计划，固定成员由 Host 解析；评审可选，前序成果完整中转。无依赖阶段的 Host 并发预留已测试，两条绑定都持久化；真实模型同时发起多个阶段的视觉体验尚未验收。
- 真正交付：export_file 经原生 Bash 沙箱写真实 ZIP、读回核对、原生 present；包含空格和引号的目标路径纳入原生测试。已有不同内容拒绝覆盖。
- 创建/修改/转换/批量方法：创建 Skill 使用原版四份规范，补齐材料盘点、领域内容保留、逐作品查重保存校验和整团交付。流程文本的专业产出质量仍需实际模型试用，不能以静态规范存在当作商业质量验收。

不将二进制资源、单成员直调和可选评审列为永久排除项。没有安装 preview、没有付费模型专业质量结论、没有本轮浏览器视觉验收；因此代码能力覆盖与完整产品体验验收分开记录。

## 专家中心页面分工（用户截图纠偏）

专家中心用于发现；“我的专家”是独立作品管理页，分专家/专家团标签，真实按作品类型查询、搜索与分页。各类型提供独立创建入口，跳到官方新任务与原生输入框，分别填入专家或专家团的自然语言草稿，不自动发送。详情用于了解使用，完整文件编辑继续单独打开。卡片突出职业、简介、领域标签与真实头像，管理状态保留在管理页。

官方复用记录：D04/D11，现有 main Slot、官方 layout selectPanel 与 Session/input.overlay 草稿交接，不复制新任务页/编辑器；Host list 同一服务增加 expertType 条件与摘要展示索引，无新存储或执行接口。验收：类型查询计数分页、草稿入口分流、构建/类型检查；浏览器视觉验收单列。

专家中心分类纠偏：中心与我的作品均直接提供专家/专家团切换，卡片显示类型。复用既有公开 main Slot 与同一 Host list expertType 条件，不新增目录或执行器。

专家团详情使用面（2026-09-13）：既有 ExpertDetail 已发布定义作为展示源，复用同一 onSummon→官方Session/输入草稿管线；简介/标签→快捷提问→主理人与成员，职业与显示名从原始Agent frontmatter作只读投影。完整专业MD和技能版本诊断折叠保留，不另建业务状态，不改发布修订，不伪造头像/用量。成员点击仅查看职责，不绕过主理人绑定执行。
