## 有限后续方案

1. **指令基线**：本轮已修正按需读取及阶段依据；后续只在出现重复、冲突或失效证据时清理，不推翻插件架构。
2. **技能质量建议**：沿既有 Skill 管理服务提供诊断，由用户审阅修改；格式错误仍沿原校验拒绝，质量建议不自动阻止安装。需在现有技能模块版本和开发台账内登记后实施。
3. **专家与工具提示词**：审查现有 persona 与工具描述的实际组合，保留目标、领域方法、边界、交付物；长篇示例和分支流程按需引用。不能静默修改已发布修订或运行中任务。
4. **对照评估**：相同输入、模型、推理配置、技能修订、授权与工具版本，比较原版/精简版；分别评估 Astra 和项目实际使用模型，不先承诺收益。

## 评估与完成标准

覆盖代码修复、技能创建、专家分析、PPT/Word 文件交付、失败/权限拒绝六类任务。记录技能选择准确性、无关技能加载、总输入/输出 token、耗时、追问/提前停止次数、工具回执及最终成果可用性。通过官方日志和已有测试扩展观察，不新增执行器；token 统计不可得时标注缺失。

代码任务以实现与相关检查通过为准；文件任务以真实文件输出、可打开且内容检查为准；分析任务保留来源与事实边界；发布任务需授权及远端回执。错误、拒绝、缺凭据应给出准确诊断，不为了完成率绕过权限。每类准备多个固定用例、重复运行，展示逐项结果和波动，不以一次成功或低 token 作为整体通过。

本轮未修改产品运行代码、用户技能、专家修订或 Profile。模型 A/B、真实成品评估及全量构建测试未执行；后续产品建议未实现，不改变 currentStep 或启动后续插件。

本轮验证：计划检查通过（28 模块、50 文档），审查引用源码存在性、Markdown 围栏与 git diff --check 通过。计划检查仅证明文档/脚手架完整性。

## 第一项落地：只读技能质量报告

工具：`scripts/quality/audit-skills.mjs`。运行 `corepack pnpm audit:skills <目录> [目录...]`，输出 JSON；`corepack pnpm test:skill-quality` 运行相关检查。无需 API Key，不连接模型、不写用户技能、不加载技能脚本。不指定目录时显示用法并返回 2；读取失败返回 1，有建议仍返回 0。跳过符号链接、node_modules、.git、.artifacts；不等于官方技能发现结果。

官方能力复用记录：任务为项目指令审查的只读工程辅助，不新增业务插件。查阅 `docs/dsh-v0.1.6-alpha.2/subsystems/skills.md`，技能注册、合并、正文加载及运行继续由官方 ctx.skills/filesystem/tool-skill 拥有；本工具仅读取用户明确指定的文件，用技能包现有 YAML 依赖解析元数据，不模拟官方加载器。未改插件版本、契约、Profile 或 currentStep。

现阶段检查：YAML 元数据是否可读、描述是否存在、描述超过 240 字符、正文超过 12000 字符、部分全局触发措辞、所选文件完全相同的描述。两个长度阈值是可审阅启发式，不是官方限制；英文/中文计数是 Unicode 字符数，不是 token。相同描述可能属于不同作用域；工具不判断实际运行时冲突。示例或引用中的措辞可能误报，必须人工核对。元数据读取异常也不直接宣称官方 Harness 拒绝该文件。

本机只读扫描：215 个技能文件、139 个含建议；描述长 119、入口长 41、元数据不可读 9、缺可读描述 9、广泛触发措辞 4。分类可重叠。报告保留在 `.artifacts/skill-quality-report.json`，含本机路径，不纳入公开发行。扫描数量不代表会话模型实际可见技能数量。

验证：3 项相关测试通过，覆盖多行 YAML、格式异常、准确/全局描述、重叠目录去重、符号链接跳过、重复描述及源文件保持不变。产品 UI 诊断接入、语义冲突检测、模型 A/B 和成品验收未执行。此工具先用于审查，不能以报告数量证明性能或品质改进。
