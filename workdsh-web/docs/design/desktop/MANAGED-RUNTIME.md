# Desktop 托管 Python 与技能依赖设计

日期：2026-09-13。状态：用户已确认方向，待实现与官方扩展面验证。本设计不代表 Desktop 已自带 Python，不启动 Excel 格式、合并或图表开发。

## 目标与职责

普通用户不需要预先安装系统 Python、pip 或 Docker，就能运行我们明确支持的 Python 技能。Desktop 负责提供解释器、依赖和环境诊断；Harness 继续拥有 Agent loop、工具调用、授权、审计、取消和沙箱。运行环境决定“用什么执行”，沙箱决定“可以访问什么”，两者不互相替代。虚拟环境仅隔离依赖，不是安全沙箱。

官方能力复用依据：锁定 `@deepseek-ai/dsh@0.1.5-rc.1`（2026-09-18 补记：本段写于 rc.1 时点；全仓当前锁定 `0.1.6-alpha.2`），参见 [sandbox](../../dsh-v0.1.6-alpha.2/subsystems/sandbox.md)、[ptc-runtime](../../dsh-v0.1.6-alpha.2/subsystems/ptc-runtime.md)、[Desktop 打包 ADR](../../adr/0025-desktop-packaging-via-official-pipeline.md)。本地 sandbox 是同宿主进程权限策略，不包含 Python。已发布的 PTC 运行时提供方为官方 sandboxed Node（2026-09-11 官方决定，见 `subsystems/ptc-runtime.md`）；实验性私有 Python 后端不作为依赖。容器仅为可扩展方向，本方案不宣称官方已有容器后端。

本机 WorkBuddy 对照证据：应用 Resources/vendor 中有 python.dat、node.dat，用户 ~/.workbuddy/binaries/python 中有托管解释器和默认依赖环境。本设计借鉴托管职责，绝不复制其二进制包、私有实现或以此推断所有平台实现一致。

## 分发与初始化

1. 从可合法分发的上游构建或获取可重定位 CPython。解释器版本、平台、架构和来源在发行清单中固定；首批目标跟随实际 Desktop 支持矩阵，不虚构多平台已通过。
2. 随 Desktop 制品交付解释器和精选依赖的离线资源。首批候选包括 openpyxl、pandas；最终库清单须经过依赖、包体积、许可证和实际技能测试确认，不承诺全部 Python 技能兼容。
3. 首次使用部署至 Desktop 官方应用数据目录下的 WorkDSH 托管子目录。实际目录由官方应用数据路径接口决定，不能写死开发机、.test-runtime 或应用只读资源路径。版本目录不可变，以原子切换启用；资源校验失败不执行，失败初始化可重试。
4. 安装、升级与回滚保留独立回执。应用更新不删除用户技能、成果或仍被任务使用的旧环境；清理须确认没有活动引用。
5. macOS 签名、公证与嵌套二进制/动态库验证、Windows/Linux 对应发行要求，以及 Python 和所有传递依赖的许可证文本、来源与版本清单，均为发布门禁。

## 执行集成

技能 → 托管解释器与依赖 → Harness 官方执行工具及本地沙箱 → 授权文件和成果。

优先通过官方 Desktop/Profile/执行提供方支持的环境配置，将托管解释器目录提供给正式 Bash/PowerShell 执行环境，并注入可校验的运行环境说明。设置环境必须覆盖同一执行 Host；远程 Host 使用其自己的已验证环境，不能把本机路径传给远端。

实施前必须用锁定发布包 exports/types 与最小探针确认：环境配置接口、子进程环境继承、沙箱解释器/标准库/依赖读取策略、工作区写入范围、超时和取消。如果没有公开接口，记录缺口并向上游提出需求；不改 Harness 源码，不另造 Bash、Agent loop、通用执行器或容器平台来绕过它。

解释器/依赖目录默认仅允许读取，成果写入任务授权范围。依赖准备与技能执行分离，准备阶段有明确权限和网络策略，执行阶段不自行扩权。禁止静默回退到系统 python3；托管环境失效须报告真实原因。虚拟环境和容器标签均不替代实际沙箱验证。

## 技能依赖与状态

内置常用环境提供基础离线能力；需要额外依赖的技能使用隔离环境，并固定依赖版本和平台 wheel/哈希。首次额外安装显示下载来源、影响范围和失败原因，按既有用户/组织授权策略执行；不要求 sudo、不安装到系统全局。无网络且资源未缓存时明确不可运行。

依赖声明是 WorkDSH 待设计的安装/可运行性元数据，须先补契约和授权设计；不擅自添加不兼容的官方 SKILL.md frontmatter，不由模型文本自证依赖可用。安装冲突、版本不兼容、资源缺失、准备失败和结果未知分别诊断，不能通过反复执行猜测成功。

技能至少区分“草稿已创建”“已发布/安装”“环境已验证可运行”。发布回执不能代替可运行性验证；未知第三方依赖不保证开箱即用。不得为了使用托管环境改写用户已有技能。

## 实施顺序与验收

- RUNTIME-01：公开面探针和分发清单；确认解释器可重定位、平台/架构匹配、环境继承与沙箱边界。
- RUNTIME-02：首批 Desktop 内置 Python 与精选依赖；离线部署、原子启用、诊断和回滚。
- RUNTIME-03：额外技能依赖声明契约、隔离准备与可运行性检查，保留安装和运行的独立状态。

上述是 Desktop 发布前置切片，仍待实现；不改变 D04 当前主线或宣称 D15 完成。

必须验收：没有系统 Python 的干净机器完成 Excel 样本读取、技能调用和真实成果输出；首次使用离线可运行精选库；两技能依赖冲突互不影响；沙箱允许解释器读取却拒绝未授权文件访问；取消/超时无遗留子进程；损坏资源和不匹配架构明确失败；升级/回滚不丢用户数据；远程任务不误用本地路径；发布制品签名、许可证与来源完整。

未执行：托管环境实现、跨平台打包、干净机器和真实模型端到端验收。默认方案不要求用户安装 Docker；容器/远程多人执行后续另做架构与官方接口评估。
