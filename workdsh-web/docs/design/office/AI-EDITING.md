# 八类编辑器与 AI 同文档协作

日期：2026-09-12。用户已确认需求；接口是拟定契约，尚未注册为可调用工具。
修订说明：具体身份、模型、提交、同步、人工交接与导出规则以 [UNIFIED-API v0.4](UNIFIED-API.md) 为实现依据；官方模式/子智能体与锁定版本选择见 [HARNESS-INTEGRATION](HARNESS-INTEGRATION.md)。本文件保留产品目标，以下能力表是八类目标范围，不表示已实现。

## 产品目标

用户在原生对话中说“写一份调研报告”，右侧自动打开报告，标题、章节、表格依次出现。AI 通过结构化工具修改文档；用户在同一编辑器直接修改；AI 下一次读取获得已提交的最新修订。停止生成保留已提交部分，重新打开仍存在。页面展示真实提交结果，不播放模拟打字动画，不等最终下载文件后才刷新。

覆盖文档、演示、电子表格、PDF、画布、多维表格、HTML、Markdown，均有手动入口和能力明确的 AI 接口。不以工具数量、空页面或引擎 API 测试代替完整交付。HTML与Markdown是正式类型，必须支持编辑、AI分批写入、保存和重开。

## 操作与能力

| 类型 | AI 结构化操作 | 原生页面反馈 | 边界 |
| --- | --- | --- | --- |
| 文档 | 插入/更新段落、标题、列表、表格、图片；读取选区与大纲 | 正文逐段出现，更新位置短暂标记 | DOCX 导入导出保真另验，不等同原生 JSON 文档 |
| 演示 | 增删幻灯片、修改文字/图形/位置、表格和支持的图表数据 | 对应页更新，缩略图跟随 | 不支持对象不得静默丢失 |
| 表格 | 范围读取/写入、工作表、基础格式、支持的图表 | 单元格范围更新 | 沿用现有公式能力，不新增计算引擎 |
| PDF | 添加注释/文字覆盖层、填写表单、页面插入/删除/排序 | 目标页更新 | 无原有正文编辑能力时明确拒绝，不能覆盖文字就称重排正文 |
| 画布 | 创建/修改图形、连线、文字、分组与位置 | 对象逐个出现或修改 | 对象必须有稳定 ID |
| 多维表格 | 定义字段类型、增改记录、建立关联、视图筛选排序 | 记录、关联与视图更新 | 普通单元格网格不能代替记录/字段/关系模型 |
| HTML | 新建/修改HTML、CSS、JS源码文件，定位源码范围、引用受管资源 | CodeMirror源码与隔离页面实时更新，可切换/分屏 | 预览不获得Host权限；源码提交与预览成功分开，导出包含所需资源 |
| Markdown | 增改章节、段落、表格、任务列表、代码块、Mermaid、公式 | Tiptap正文编辑与CodeMirror源码切换，同一修订 | 原始语法/未知块保留；.md往返，源码与正文不能各存一份独立内容 |

每个适配器返回明确的 capabilities（含 read/write/export 与具体 operation）；只有实际实现并通过测试的能力对模型可见。

## 架构决策

AI → Harness 原生工具 → 文档领域服务 ← 官方 Connection ← 编辑器页面。
文档领域服务提交修订 → Client model 查询已提交修订 → 编辑器适配器应用更新。锁定rc.1先用认证exact Fetch和受控修订查询，后续生成Remote/流式通道通过公开面探针后再迁移；不假定domain/changed自动广播到浏览器。
外部 MCP 是同一服务的可选适配入口，不另建 MCP 服务端、执行器、模型连接或写入状态源。首期内部 AI 使用原生工具即可；是否能通过锁定 Harness 的 MCP 公开能力导出工具需单独验证，不能预先宣称可用。

Office 拥有编辑工作副本、操作收据及修订；已导入资源/正式成果的归属继续由现有文件服务和未来 library 管理。引用原始资源 ID 与基线哈希，不创建第二套资料库。渲染/转换在浏览器，Host 仅做授权、操作持久化、修订和订阅，不安装 Office 或运行转换服务器。浏览器不可用时，依赖浏览器的导出返回等待客户端/不支持，不伪称已生成文件。

八类可采用不同编辑器及原生数据模型；统一的是会话、权限、版本、收据和能力描述，不强制八类套同一万能 JSON 文档模型。按类型按需加载，通过 Harness Loader/Profile/公开服务组合，不新增通用插件框架。

部署单位为独立`workdsh-plugin-office`，内部内容服务/工具/Connection与Client适配由官方Cordis组合，详见[插件架构](PLUGIN-ARCHITECTURE.md)。多维表格为Office独立内容文档，HTML为源码/预览，二者不接管tables业务数据库或pages发布。工具、UI、其他消费者走同一公开领域服务；卸载保留已保存内容并撤销能力。

## 拟定 API（尚未实现；已由统一方案收敛）

八类共同使用content_open/read/capabilities/edit/present/export；具体严格分支见 [UNIFIED-API](UNIFIED-API.md)。open同时处理新建、已有资源与重开；工作副本contentRef和真实文件resourceRef区分。旧office_*与未发布content_create不再作为实施名称。

身份从 ToolRunContext/Connection 和既有 runtime binding 解析，不允许模型传 actor/organization。目标定位使用稳定ID或绑定修订及前置文本的源码范围；禁止以工具直接eval模型程序、DOM selector或自行打开shell。HTML内JS是文件内容，只在受限预览中运行，不变成Host工具执行入口。跨插件只消费公共契约。

## 修订、并发与失败

1. Host 作为编辑工作副本提交的唯一排序者。每次请求必须携带 baseRevision 和 operationId；操作去重范围包括主体、文档与请求 ID。相同 ID 不同负载拒绝。
2. 原子批次只生成一个新修订；校验/授权/提交失败不广播成功。持久化完成后才发事件、返回提交回执。不能只在浏览器内存操作就宣称保存。
3. 页面经认证Connection提交手动修改；本地未提交编辑显示状态。人工lease暂停AI对该文档的新提交，revision CAS拒绝过期写入；输入法组合结束再保存，不新增CRDT。
4. Client model有界查询revision/hash与快照，断线恢复后立即校准。将来事件通知只是加速提示；重复/延迟响应不得倒退，无后续写入也能检测快照窗口的变更。接收提交不再次回写。
5. 同一文档多标签共享修订；后台标签不强抢焦点。用户主动选择“跟随 AI”才滚动到当前编辑区域。
6. AI 以段落/幻灯片/单元格批次提交；页面平滑展示已提交批次。工具调用不能被当作模型 token 流，无法保证逐字实时生成。
7. 取消在提交前检查 signal；已提交批次保留，未提交批次中止。提交已成功但回执中断时按 operationId 查收据，避免重复段落。
8. 撤销只提交本客户端事务的带前置条件逆操作，不能整体回滚其他修改。人工失联缓冲保留，重新接手后合并；已暂停Agent通过官方“继续”入口恢复，不假设inject会唤醒。
9. 外部源改动通过基线哈希检测并保留工作副本。导出固定revision/输入hash/adapterVersion，首版只写副本；下载提供与已保存资产回执分别报告，不支持任意旧修订导出。
10. 每次操作重查所属主体/组织/会话授权；未知文档不得枚举他人内容。工作区真实路径限制和符号链接检查沿用授权文件入口。文档内容不作为权限指令。

## 页面体验

右侧原生 Tab 显示文档，顶部只保留标题、保存状态、跟随 AI 和必要操作。状态区分“正在编辑”“已保存”“保存失败”“冲突”，无前端确认时只报告文档已提交，不能报告用户已看见。AI 工具回执提供可点击资源引用，打开入口复用官方 Sidebar API，接口存在性先核对。

用户直接点击文字/对象编辑；不再追加文字片段输入区。多格式统一按钮语义，不强行复制八套厂商首页、登录、云盘或 AI 对话入口。导出不支持的复杂对象明确列出，禁止静默降级。

Markdown正文/源码、HTML源码/页面均在同一右侧Tab内切换或分屏。Markdown支持正文原生输入；HTML首版提供完整源码编辑与实时交互预览，不声称任意页面都已支持可视化拖拽设计。视图切换不新建工作副本，不丢本地未提交输入；预览错误不抹掉已保存源码。

## 有限交付顺序与验收

A：选型/许可、拟定契约、官方工具/Connection/存储/Tab公开面验证（U1）。
B：文档首条真实纵向链路：创建 → AI分批写三段 → 页面实时显示 → 用户改第二段 → AI读取最新值 → 继续写 → 保存/重开；补已有资源入口与故障/导出闭环（U2—U3）。
C：同一服务按Markdown→HTML→Excel→PPT→PDF→画布→多维表格扩展，逐类兑现上表的原生操作与文件能力；全部保留范围，不让一个编辑器阻挡其余类别（U4）。Markdown正文/源码往返、HTML资源包/脚本隔离/错误预览有独立验收场景，详见统一API第11节。
D：真实文件保真、断线、取消、并发、权限、无外部请求、包安装/卸载及统一发布验收（U5）。子智能体不作为上述交付前置。

首条链路验收：非模拟 Agent 工具调用能产生有持久收据的修订；已打开页面在本机正常条件下目标1秒内反映提交（记录实际延迟，不宣称硬实时）；手动修改不会被过期 AI 请求覆盖；刷新可恢复；取消保留已提交部分；同 operationId 重试不重复写；非 owner/跨组织/其他会话不获得文档；无第三方文件上传。先用确定性工具调用验证，再做真实模型验收，两者分开记录。
