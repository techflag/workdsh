# ADR-0017：专家定义经不可变修订绑定原生任务

状态：Proposed（方案已整理；实现须通过公开接口关卡）
日期：2026-09-12
关联：D04 / P1-02；团队 D11 后续。

## 背景

用户要求参照 WorkBuddy 的专家、专家团及 expert-manager 对话制作流程，形成可交接技术文档。当前专家目录仅规划占位，本地 Skill/治理/工作台能力可复用，但尚无专家领域和全路径运行绑定。ADR-0010 已要求不可变 preset；本决策将其落实为专家业务设计，未宣布实现完成。

## 决策

1. 一个专家插件管理多个 Expert/ExpertRevision；专家团后续仍归此插件。专家对象不是 npm 包。UI 与 Agent 工具只经同一 Host 领域服务写入。
2. 个人草稿可变，发布版本不可变，发布确认绑定精确定义和依赖。默认模板只读可复制；不建公共市场或企业服务器。
3. 专家角色经官方 persona 的 preset scope 编译，原生 Session 保存执行事实。不可把用户数据当任意 Cordis 配置或修改全局 persona；不禁用官方运行上下文。
4. 固定专家显式声明的 Skill 快照；未声明的全局 Skill 保持原生动态能力。快照由 Skill owner 的公共契约提供，专家不能越界读取其私有实现。内容冻结不等于权限冻结。
5. 创建经受控 Session 入口与指定 SessionId 进行幂等对账；召唤/示例只准备原生草稿。非空任务换专家创建关联新任务。
6. 所有绑定 Session 的原生执行/恢复/fork/换 preset 路径必须通过 G03 公开 seam 验证。只保护自定义页面入口不能通过验收；缺口不允许靠修改上游或静默降级填补。
7. 首选官方 Typert Remote。若专家最小生成探针仍失败，须补专家专属证据与本 ADR 的后续决策，再选官方 Connection exact Fetch 本地例外；本文不预先批准任意 RPC 通道。
8. 管理状态用官方 Storage Domain，跨构件/发布头/Session 采用持久操作记录与补偿对账，不宣称跨域事务。取消按实际提交边界解释。
9. 团队采用真实原生子代理协作；实验性 Agent Team 未在当前 lock 中，不依赖其最新文档直接实现。企业服务器、管理 Web 和组织发布继续后置。

## 取舍与影响

相比临时注入提示词，业务修订与依赖引用增加适配工作，但可保证旧任务不被角色编辑悄然改变。相比自建 Agent runner，复用原生能力减少重复系统，同时必须先证明公开接口覆盖恢复与隔离路径。未来企业适配可以复用 owner/引用模型，但本文不声称当前本地边界已经满足多人服务。

备选：只做专家管理/草稿原型，可在关卡未完成时用于评审，但不能当单专家 0.1 交付；单 Agent 扮演多人不可当专家团；直接修改 preset 原文件违反 ADR-0010。
