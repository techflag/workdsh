# ADR-0021：专家与专家团作为完整制作作品

状态：实施中，2026-09-13，用户明确授权。

问题：制作 Skill 只能逐个创建单专家，运行 SOP 与可复用团队没有连接；导出仅有 JSON，专业内容和用户交付脱节。

决定：复用现有 ExpertsManager、官方 Storage Domain、Agent Presets、Skill 快照、原生 Session 和受控团队委派。一个专家团以主理人的 ExpertDefinition 为聚合根，附带完整成员定义与可复用场景；不新增第二个目录或执行器。单专家的旧数据与 API 保持兼容。

- 草稿保存整个作品。成员是内容快照，可从已有专家内容复制；不跟随来源专家后续编辑。
- 一次预览/确认绑定整个定义及所有成员技能依赖。发布先冻结成员，再发布主理人；未完成的子成员不出现在公共目录。重试复用相同内容的成员，不能提前暴露可用团队。
- 已发布团队固定成员修订。新任务使用当前版本，已有任务保持原绑定。团队停用同样阻止其内置成员的新执行。
- 场景区分主理人直接处理和需要协作的任务。协作场景接入现有 SOP 的真实执行与评审；不把自然语言规则冒充运行时权限。当前 SOP 要求独立评审者，编辑界面不向用户暴露流程图配置。
- 完整文件包是专业内容的创作源；Host 的结构化定义仅承担索引、兼容投影和运行状态。保存整包时重新解析身份、角色、依赖与成员，不允许只修改摘要造成双重真相。导出包含主理人、成员、协作说明和使用说明；受检包导入保留内容，但重新生成身份和修订，不导入权限或执行代码。
- Skill 负责需求提炼、领域方法、成员分工、典型问题和具体成果。TypeScript 只负责结构、存储、校验、编译与调用。无需 Python 才能制作/安装专家。

取舍：采用已有专家聚合而非新增 TeamRegistry，复用既有发布、确认、导入导出、卡片与任务生命周期。成员不会被独立修改；需要独立使用时复制成员内容为单专家。自由多轮群聊不属于这次实现，现有 SOP 保障继续保留。

验证：完整团队保存/一次确认/发布/冷读；成员内容或依赖改变使旧确认失效；结构错误和越权拒绝；团队修订正确映射到真实成员；包导出/导入往返；单专家回归。测试结果写入 STATUS，不以无真实模型的测试宣称专业效果已验证。

2026-09-13 修正：四份 WorkBuddy 原规范原样保留，平台差异独立文档。自由 Agent MD、包内 Skill/references/scripts/templates 文本资源保存、发布、官方挂载及导入导出往返已接入。编辑界面直接编辑原文件。单成员直接委派、自然语言 Workflow 自动编译及二进制头像/bin PATH 安装仍不在已完成范围。

用户追加授权：完整覆盖WorkBuddy expert-manager制作与交付能力。补齐二进制资源、单成员真实调用、按正文编排的可选评审/串并行、原文回传、完整包实际文件交付；不再将这些能力永久排除。验收见WORKBUDDY-COVERAGE。

本轮实现更新：此前“评审必需”及“单成员/二进制仍待实现”描述为历史切片。现已增加真实单成员 team_ask、可省略外部成员绑定的正文计划 team_open、可选评审与完整前序输出中转；二进制资源、实际头像、可执行 bin 文件、真实 ZIP/present 接入同一作品服务。bin 使用固定作品目录中的绝对路径，不修改宿主全局 PATH。创建 Skill 增补原材料/仓库转换与批量制作纪律。覆盖/证据边界见 WORKBUDDY-COVERAGE；不能据此声称视觉及模型专业质量全面达到 WorkBuddy。
