### 验证规则

**“暂时未找到接口”是待调查状态，不是“功能无法实现”，也不能作为删功能或提前结束任务的理由。** 每项能力依次验证：官方默认组合 → 官方配置组合 → 官方公开 Service/Provider/事件/Guard/Remote 扩展。修复依赖、作用域、创建时序或调用方式问题后必须重跑失败用例。

静态类型审查只用于提出假设。使用确定性模型驱动真实 Loader、AgentLoop、Team、Session 和 Skill 服务，避免用模拟的创建成功或模型自述代替执行事实。确认接点后，再用实际模型和认证 Web Profile 验证用户流程。

验证状态使用：待验证、验证中、通过、失败待定位、当前版本公开契约限制已证实。最后一种状态必须附最小复现、全部候选路径的测试结果、官方依据和具体受限行为；不能推广为“整个功能无法实现”。遇到限制继续提出并验证官方支持的组合方案，迁移关卡保持未完成，不擅自删除目标或降低验收标准。

6. 专家或 Skill 源内容在成员创建后发生修改，已有成员仍使用原绑定；无权限、伪造映射、撤权、重复创建、创建中取消均不能产生可绕行的半绑定任务。覆盖普通任务、单专家及团队三种入口的工具可见性。

- DSH 依赖、overrides、锁文件和制品运行依赖统一精确版本；旧 code-runtime/workflow-worker-thread 名称迁移至官方 `ptc-runtime` / `workflow-ptc`，依据实际 exports 调整。

### 专家团与 UI

#### 自有代码替换清单

2026-09-15 的隔离实测确认：官方默认 Team 无需 WorkDSH binding 即可运行；公开 `agent/created` 配合 `agent.ctx.plugin()` 挂载官方 Persona/Skill Filesystem，能在共享运行 preset 下区分 A/B 队友的角色与技能，并由官方消息服务跨进程唤醒原队友。`agent.ctx.loader.create()` 本次会把 Persona 落到错误注册层，不能作为局部挂载写法。完整结果、未通过的分叉查询与边界见[证据](evidence/dsh-0.1.6-official-integration.md)。此结论支持以下替换方向，不等于已迁移用户专家。

| 现有位置 | 替换/缩减方向 | 删除前核对 |
| --- | --- | --- |
| `runtime/delegation-provider.ts`、`runtime/delegation-wait.ts` | 删除自有 one-shot 创建、等待、输出结算与续跑责任，交给官方 Team/continuable subagent | 原生取消/恢复、专业签收、用户历史迁移及生命周期通过 |
| `runtime/preset-compiler.ts` | 不再为每个专家复制整套基础运行 preset；以官方共享组合承载运行，角色与技能使用官方局部插件，仅保留作品格式转换/资源发布所需部分 | 完整专家作品、二进制资源、固定版本、首请求与重启后角色一致；本轮只验证固定测试资源，未验证发布迁移 |
| `services/experts-manager.ts` 的执行计划/委派预留与 claim/binding | 拆出并移除重复运行身份管理，使用官方 Lead/teammate/Session；只在确需的作品版本、准入和资源关联处保留薄适配 | 逐项验证官方接点能承担的校验，不为沿用旧 binding 人为阻止原生运行，也不遗漏授权或用户作品 |
| `services/team-runs.ts` 的工作依赖、成员运行与尝试控制 | 原生任务板和成员状态作为执行事实；按业务需要仅保留专业评审与文件版本签收规则 | 原生 completed 与专业验收的区别、指定评审者、返工、文件变更反例，避免留下第二份运行状态 |
| `tools/team-tools.ts` | 创建、委派、消息、等待、中断使用官方工具；旧同职责工具退出新团队组合 | 工具可见性、普通/单专家/团队入口、PTC 直调和失败返回；专业验收工具按实际职责评估，不按前缀批量保留或删除 |
| 专家制作/导入导出及活动 UI | 优先使用官方配置创作、资源与状态接口；仅保留 WorkBuddy 格式兼容和所需产品呈现 | 不丢已有专家作品；来源到官方配置可追踪；状态来自官方查询，不能将源代码减少等同于删除用户功能 |

下一验证项为固定作品映射与官方工具 Guard/专业验收；分叉历史查询异常同时以原生组合复现并验证公开读取路径。该异常已与“分叉成员可执行、可续跑”分别记账，不据此否定整条迁移路线。上述文件目前仍服务现有产品，未通过替换门槛前不先删掉运行路径。

- 通过 V1—V3 后，使用官方 Team/Profile 运行、官方 `spawn_teammate` 与其余团队工具；移除旧的运行委派路径与冲突工具注册。专业评审和文件验收的业务检查按验证方案保留并接入，不因工具名称前缀批量删除。
- 保留稳定业务专家团/运行记录标识，显式关联官方 Lead Session/Team ID、子 Session 与固定专家修订；Team ID 不覆盖既有业务主键。teammate 名称遵守官方唯一及不可复用约束，UI 使用关联后的业务显示名。
- 官方日志是 roster、mailbox 和任务执行事实的唯一来源；WorkDSH 只保存业务定义、修订、绑定和验收回执，不自建执行状态真源。
- 老任务保留可读记录，升级前的在途任务不得静默转换；续跑兼容性在数据副本上单独验证。新版不具备受支持恢复路径时给出具体迁移状态与旧环境回退方式，不能用创建新任务冒充历史恢复。
- 自有展示使用公开 Slot/Remote 和既有授权接口；官方未暴露的字段不能推测生成。认证后的真实页面截图须覆盖不同成员运行、等待、失败和重启恢复。
