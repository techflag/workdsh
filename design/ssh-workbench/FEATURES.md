# DSH Terminal：功能清单与交互需求

> 编号：PRD-DSH-SSH-001 · 版本：0.1 · 状态：待评审草稿 · 日期：2026-09-08
>
> 产品名称暂定。本文定义目标功能，不表示这些功能已经存在于 DSH Desktop。原型中的服务器、模型、命令与文件均为模拟数据。

## 1. 产品目标与范围

做一款面向个人开发者和运维人员的 SSH 桌面工作台：可以管理主机、操作终端和文件，并免费接入用户自己的模型，在工作过程中随时得到上下文相关的 AI 帮助。

### 1.1 已明确的用户需求

- 借鉴 XTerminal 的 SSH 工作台体验，基于 DSH Desktop 演进。
- 用户自己配置大模型，避免模型接入受到产品 Pro 付费限制。
- 使用过程中随时呼唤 AI 帮助。
- 当前先交付详细功能清单与可点击原型。

### 1.2 本版设计假设

- 个人开发者、运维人员为首要用户；第一版无需产品账号即可使用核心能力。
- macOS 与 Windows 为首轮桌面验证平台；远程 Linux Bash/Zsh 优先。
- 第一版重点是 SSH、基础文件操作和 AI 建议；受控自动执行列为 P1，但在原型中提前展示以便评审。
- 产品名 DSH Terminal、优先级和界面文案为提案，尚未获用户逐项批准。
- 模型接入免费不代表云模型调用免费。云模型调用由提供商计费；本地模型使用用户的计算资源。

### 1.3 分期范围

| 优先级 | 数量 | 交付含义 |
|---|---:|---|
| P0 | 45 | 首版形成完整日常工作流程，发布前必须满足 |
| P1 | 16 | 下一阶段增强能力；原型包含部分交互预览 |
| P2 | 8 | 后续扩展，当前不承诺实现或排期 |
| 合计 | 69 | 功能与质量要求均包含独立编号及验收条件 |

当前不纳入首版：RDP/VNC、移动端、团队云同步、多主机自动批量操作、云账号体系、收费与订阅系统、通用自主修复任意服务器。

## 3. 用户旅程

### 3.1 首次使用

打开应用 → 跳过账号流程 → 添加主机或打开本地终端 → 核对指纹并连接 → 可选配置模型 → 进入工作区。

模型配置不应成为手工使用终端的前置条件。未配置时保留问题草稿并引导配置。

### 3.2 终端报错求助

执行命令 → 看到错误命令块 → 点击“分析错误” → 查看引用与模型 → AI 给出带解释的建议 → 用户复制或填入 → 用户回车执行 → 查看结果并继续追问。

### 3.3 受控协助（P1）

选择支持工具的模型 → 切换协助模式 → AI 提出具体操作 → 确认主机、目录和完整命令 → 执行并显示结果 → 必要时提出下一步验证。

### 3.4 文件修复（P1）

配置检查失败 → 查看对应文件 → 询问 AI → 查看差异与备份计划 → 确认保存 → 再次验证语法 → 决定是否重新加载服务。

### 3.5 异常与恢复

| 异常 | 用户可见行为 | 恢复方式 |
|---|---|---|
| SSH 认证失败 | 明确失败原因范围，不回显密码 | 编辑凭据或重新输入 |
| 主机指纹变化 | 停止连接并展示变化 | 用户通过可信来源核对 |
| 网络断开 | 保留输出，禁用提交，状态为断开或未知 | 显式重连，绝不自动重放命令 |
| 模型未配置 | AI 暂不可用，终端可用 | 保留问题并进入模型设置 |
| 模型认证失败/超时 | 显示区别明确的错误，保留配置 | 修改后重新测试或手动重试 |
| 模型不支持工具 | 允许问答，协助模式不可用 | 选择适用模型 |
| AI 生成被停止 | 标明停止，不继续发起操作 | 继续手工操作或重新提问 |
| 用户切换标签 | 恢复该目标的终端和 AI 会话 | 原目标请求仍绑定原目标 |
| 文件外部变化 | 告知冲突，阻止静默覆盖 | 重新加载并比较 |
| 未知执行结果 | 明确未知，不能显示成功 | 用户检查目标状态后决定下一步 |

### 4.1 共用交互规则

- “填入终端”不发送回车；“执行”与“保存远程修改”必须展示具体目标及内容。
- 每个终端保存自己的输入草稿、AI 对话及上下文选择。
- 关闭 AI 面板不关闭终端；清空 AI 对话不清除终端输出。
- 当前请求使用发起时的模型和目标；切换模型不自动重发历史。
- 生产标签在主机、终端、AI 和确认页一致显示。
- 弹窗支持键盘操作、焦点约束、Esc 和返回触发入口；未保存修改需确认丢弃。
- 原型公开标注“模拟”；固定指标、示例模型与场景回答不是在线检测结果。

### 4.2 原型状态覆盖边界

原型可体验：已有连接、首次连接指纹、显式断开/重连、命令成功/报错/未知样例、AI 生成/停止/超时样例、模型测试成功/认证失败/超时/仅聊天、列表无搜索结果、未保存编辑、模拟传输完成/取消。

仅定义需求，当前原型未完整模拟：真实认证与指纹变化、真实网络重试与进程控制、任意 Shell/全屏终端程序、真正的分屏输入、真实文件冲突与备份失败、模型 HTTP 协议、加密存储、多台机器并发操作。

## 6. 数据概念与业务关系

| 业务实体 | 含义 | 关键业务属性与关系 |
|---|---|---|
| 主机配置 | 可连接的远程目标 | 名称、地址、用户名、环境、凭据引用、所属分组 |
| 终端会话 | 一次具体连接与交互过程 | 所属主机、连接状态、目录、命令记录、输入权 |
| 模型服务配置 | 用户选择的推理服务 | 协议、地址、模型、凭据引用、能力测试状态 |
| AI 会话 | 围绕某个终端的持续求助 | 所属终端、消息、引用、实际使用的模型 |
| 上下文快照 | 一次提问明确包含的内容 | 主机、目录、命令块、选区、用户主动附加文件 |
| 操作建议与执行记录 | 建议到结果的过程 | 目标、内容、原因、确认、状态、输出和时间 |
| 传输任务 | 一次文件上传或下载 | 来源、目标、进度、状态、失败原因 |
| 快捷命令 | 可复用的命令内容 | 名称、文本、标签、说明 |

一个主机可以打开多个终端；终端对应多个 AI 对话。每次模型请求使用明确的上下文快照，每个执行记录必须能回到具体目标和发起来源。

## 8. 风险、约束与发布范围

| 风险 / 约束 | 影响 | 要求 |
|---|---|---|
| 用户把模拟当真实执行 | 误判功能已完成 | 原型标题、状态和关键操作持续标明模拟 |
| AI 看错主机或过期输出 | 操作目标错误 | 会话隔离、上下文快照、重连后旧建议失效 |
| 模型能力差异 | 能聊天但不能可靠调用工具 | 独立能力测试，按能力开放功能 |
| 无 Shell 集成 | 目录、边界与退出码不完整 | 明确降级，不猜测状态 |
| 服务或网络中断 | 结果未知或误重试 | 状态可见，写操作不自动重试 |
| 凭据与敏感输出 | 数据外传 | 凭据分离、上下文预览和脱敏 |
| 上游快速演进 | 插件接口兼容风险 | 保留固定版本和原有 Desktop 行为 |
| 首版范围过宽 | 核心体验难打磨 | P0/P1/P2 分期验收；不承诺 P2 日程 |

本次设计不修改上游子模块、桌面运行代码、依赖、包管理边界或发行配置。后续实现按仓库要求在 Beta 验证，再同步共享桌面改动并通过两个受影响包的检查。

| T07 主机隔离 | A 主机发问 → 切换 B → 返回 A | 问答、命令与输入不混入 B | REQ-AI-006 |
| T08 模型故障 | 输入“模拟失败” → 再手工运行 df -h | AI 显示失败，终端仍能操作 | REQ-AI-007 / REQ-QUAL-001 |
| T09 协助执行 | 切换协助 → 执行建议 → 确认 | 展示完整目标与命令，结果入终端和时间线 | REQ-EXEC-001/002/003 |
| T10 配置修复 | 文件 → app.conf → 差异 → 保存 → nginx -t | 展示分号修复，模拟检查通过 | REQ-EXEC-005 / REQ-FILE-002 |
| T11 连接中断 | 监控样例 → 模拟断开 → 重连 | 断开时禁止输入；不重放命令，旧建议失效 | REQ-HOST-005 |
| T12 记录与收藏 | 收藏建议 → 快捷命令 → 填入 → 导出记录 | 收藏可复用，导出仅含模拟记录 | REQ-SNIP-001 / REQ-HIST-003 |

| T14 未知命令 | 终端输入无预置命令 | 显示无预置结果，不宣称真实执行成功 | REQ-TERM-002 |

这些任务是交互原型验收。真实 SSH、模型、文件、凭据、性能与兼容性要求需要实现后单独验收。
